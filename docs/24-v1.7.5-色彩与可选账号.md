# v1.7.5 色彩层次与「账号可选」

> 起因：装上 v1.7.4 之后的两条反馈 ——「感觉太素了」「账号也可以填成可选，像我一般存都是哪个平台+密码这样保存」。

v1.7.4 把一致性做完了：圆角统一、描边统一、字号统一。但统一过头就是"素"——整屏白卡片、白底、一个绿色点缀，扫过去没有落点。这一版补的是**色彩层次**，顺带把「账号必填」这个隐形门槛拿掉。

---

## 1. 账号改成可选

### 现状核对

改之前先查了一遍：数据层其实早就是可空的。

| 位置 | 改前行为 |
| --- | --- |
| `EntryDraft.username` | `String?`，`commit()` 里已经是 `username.trim().takeIf { it.isNotEmpty() }` |
| `EntryDao` 列 | `username_ct` 可空 |
| 自动填充 | `canFillUsername = usernameField != null && !summary.username.isNullOrEmpty()`，空账号只填密码 |
| 详情页 | `summary.username?.let { ... }`，空账号整行不显示 |
| 长按菜单 | `ActionRow("复制账号", enabled = !target.username.isNullOrBlank())` |

也就是说，**功能上一直可以只填平台和密码**，只是界面上写着「账号」，没有任何提示说它可空 —— 用户看到两个并排的输入框，默认理解成都要填。

### 改法

`EntryEditScreen.kt`：

```kotlin
label = { Text("账号（可选）") },
placeholder = { Text("手机号 / 邮箱 / 用户名，空着也行") },
```

只改这两行 —— 不新增开关、不做「高级模式」，标签本身说清楚就够了。

### 顺带补的显示回退

`EntryListScreen.kt` 的副标题原来是：

```kotlin
val subtitle = entry.username ?: entry.hostNorm ?: ""
```

账号和网址都为空时（只存平台+密码的典型情况），副标题整行消失，卡片看着像没加载完。改成三级回退：

```kotlin
val subtitle = entry.username
    ?: entry.hostNorm
    ?: entry.url
    ?: if (entry.hasPassword) "只有密码" else ""
```

## 2. 「太素」怎么解

素的原因不是颜色选得不好，是**颜色只在个别地方出现**：白卡片铺满一屏，绿只出现在一个胶囊、一个 FAB 上。所以这一版不是换配色，是让已有的八色头像色板**渗到页面结构里**。

### 2.1 顶部一层空气感

`EntryListScreen` 的 `Scaffold` 内容容器加 `drawBehind`：

```kotlin
drawRect(Brush.verticalGradient(
    listOf(washColor.copy(alpha = 0.10f), washColor.copy(alpha = 0.03f), Color.Transparent),
    startY = 0f, endY = 240.dp.toPx()
))
drawCircle(Brush.radialGradient(
    listOf(glowColor.copy(alpha = 0.07f), Color.Transparent),
    center = Offset(size.width, 0f), radius = 420.dp.toPx()
), radius, center)
```

- 主色从顶部 10% 淡出，**只到 240dp 就没了** —— 铺满整屏会把卡片之间的层次压平，反而更糊。
- 右上角叠一层琥珀（`secondary`）的极淡径向渐变，让绿色不孤单。
- 用 `drawBehind` 而不是加一个 Box 层：不参与布局、不拦截触摸、不影响 `innerPadding`。

### 2.2 列表行左侧色条

`EntryRow` 最左边加一道 4dp 竖条，颜色来自该条目的头像色板：

```kotlin
val accentSeed = entry.hostNorm ?: entry.packageNorm ?: entry.title
val accent = remember(accentSeed) { accentOf(accentSeed) }

Box(Modifier.width(4.dp).height(30.dp).clip(RoundedCornerShape(50))
    .background(Brush.verticalGradient(listOf(accent, accent.copy(alpha = 0.30f)))))
```

`Components.kt` 为此新增 `internal fun accentOf(seed: String): Color`，只取色板的**亮度端**：暗端（如 `#0B6E4F`）单独拿去做 4dp 细线，在白底上发脏；亮度端（`#18A87A`）配白卡片和深色背景都立得住。

### 2.3 复制按钮跟着条目走色

原来所有行的「复制」都是同一个 `primaryContainer`。改成用同一枚 `accent`：

```kotlin
color = accent.copy(alpha = 0.13f),
border = BorderStroke(1.dp, accent.copy(alpha = 0.34f)),
// 文字
color = accent
```

同一行里色条和按钮共用一个颜色 —— 两种强调色并排会打架。这样整屏扫过去：**每条记录都有自己的一点色，但饱和度压得很低，不会盖过标题。**

### 2.4 详情页顶部色面板

从列表点进详情，如果整页还是白底，会有「换了个程序」的割裂感。`EntryDetailScreen.Header` 从纯 Row 改成带渐变的圆角面板：

```kotlin
.clip(RoundedCornerShape(22.dp))
.background(Brush.linearGradient(listOf(
    primary.copy(alpha = 0.14f), primary.copy(alpha = 0.03f))))
.padding(start = 14.dp, end = 14.dp, top = 14.dp, bottom = 14.dp)
```

原来 `padding(start = 4.dp, end = 4.dp, top = 8.dp, bottom = 14.dp)` 的裸排版变成了有边界的块，头像 56dp 在这块里终于有地方站。

## 3. 为什么没做更多

| 想法 | 不做的理由 |
| --- | --- |
| 换一套更鲜艳的主色 | 主色是 `#0B6E4F` 翡翠绿，换成高饱和度的蓝紫会把「记账本」的克制感弄没；问题在颜色**出现得太少**，不在色本身 |
| 列表顶部加统计卡片 | 已经有「共 N 条」胶囊 + 筛选条上的数字，再加一块只是重复信息、多占 80dp 首屏 |
| 每行加分类色块 | 分类最多十几个，色板只有八色，撞色后分类=颜色就失效了；条目色跟站点走更稳定 |
| 引入 `material-icons-extended` | 为几枚图标引整个库，构建和体积都要付代价（v1.7.4 已经踩过一次） |

---

## 4. 验收要点

没有真机，以下几条只能装上去看：

1. **浅色**：顶部绿色光晕过渡是否自然，到 240dp 处有没有可见的「断层线」。
2. **深色**：`accent` 亮度端在 `#161B19` 背景上的「复制」文字是否够清楚；`0.13f` 底色是否显得脏。
3. **同站点多条记录**：色条与头像是否同色（应该同色，seed 一致）。
4. **只填平台+密码**：列表副标题显示「只有密码」，长按菜单里「复制账号」是灰的。
5. **详情页**：顶部色面板在长标题（两行）时是否仍然包得住内容。
