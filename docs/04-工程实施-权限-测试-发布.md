# 04 · 工程实施 · 权限 · 测试 · 发布

## 1. 权限清单与申请时机

| 权限 | 用途 | 申请时机 | 备注 |
|---|---|---|---|
| `BIND_AUTOFILL_SERVICE` | 声明为自动填充服务 | 静态声明 | 系统级绑定，用户手动启用 |
| `BIND_ACCESSIBILITY_SERVICE` | 声明为无障碍服务 | 静态声明 | 同上，敏感权限 |
| `USE_BIOMETRIC` | 指纹/面容解锁 | 静态声明 | 运行时由 BiometricPrompt 处理 |
| `POST_NOTIFICATIONS` | 待确认捕获通知 | Android 13+ 首次捕获前弹窗请求 | 拒绝则降级为仅应用内横幅 |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | 防无障碍服务被杀 | 引导页「一键前往」时 | 需应用商店说明理由 |
| `CAMERA` | 扫 TOTP 二维码 | 点「📷」时请求（CameraX） | |
| `QUERY_ALL_PACKAGES` | **不使用** | — | 会触发商店审核；改为在 A11y 事件里直接用 `event.packageName` |
| `INTERNET` | 仅用于可选的 HIBP 泄露检测 | 静态声明 | 无网络时全部功能可用 |
| `SYSTEM_ALERT_WINDOW` | **不使用** | — | 悬浮条用 `TYPE_ACCESSIBILITY_OVERLAY`，无需此权限 |
| `READ/WRITE_EXTERNAL_STORAGE` | **不使用** | — | 导入导出走 SAF（`ACTION_OPEN_DOCUMENT` / `ACTION_CREATE_DOCUMENT`） |

**Manifest 关键片段**

```xml
<application
    android:allowBackup="false"
    android:fullBackupContent="false"
    android:dataExtractionRules="@xml/data_extraction_rules"
    android:usesCleartextTraffic="false">
```

> `allowBackup=false` 必须。否则 ADB 备份/云备份可绕过主密码把 SQLCipher 库文件整体拖走（虽然仍加密，但减少攻击面）。

### 2.1 每周关键风险与对策

| 周 | 风险 | 对策 |
|---|---|---|
| W1 | KDF 参数在老机上过慢（>1.5s） | 启动时跑一次基准，按设备性能在 `kdf_params` 里选档（低/中/高档），并记录到 meta |
| W3 | 部分 App 自绘登录页拿不到 `autofillHints` | 依赖 `inputType` + `viewIdResourceName` 启发式；仍失败则由 A11y 通道兜底 |
| W4 | 浏览器域名拿不到 | `webDomain` 兜底；再失败则让用户在确认条补站点名（已在 P7 设计） |
| W5 | CSV 有 BOM / GBK 编码 | 用 `detectEncoding`（前 4KB 试 UTF-8/BOM/GBK），失败让用户手选编码 |

## 4. 构建与签名

```bash

./gradlew assembleDebug

# release（需 keystore.properties，勿入库）
./gradlew assembleRelease bundleRelease

# 检查 release 是否有明文日志
./gradlew lint release
```

`keystore.properties`（加入 `.gitignore`）：

```properties
storeFile=../keys/vaultbook.jks
storePassword=***
keyAlias=vaultbook
keyPassword=***
```

`build.gradle.kts` 里 release 打开 `isMinifyEnabled = true`、`isShrinkResources = true`，proguard 保留：
`-keep class net.zetetic.database.** { *; }`、`-keep class com.google.crypto.tink.** { *; }`。

## 5. 发布与审核要点

### 5.1 Google Play（若上架）

- **无障碍权限**：必须在 Play Console 填写「Accessibility API 使用声明」，说明：仅用于读取登录表单以捕获凭据、不用于自动化操作、数据不出设备、可随时关闭。审核可能要求提供**演示视频**。
- **自动填充**：属于系统服务，无需额外声明，但需在商店描述中说明。
- **数据安全表单**：勾选「应用不收集也不共享用户数据」（若泄露检测开启则需说明仅发送 SHA-1 前缀）。
- **敏感权限最小化**：不要申请 `QUERY_ALL_PACKAGES`、`MANAGE_EXTERNAL_STORAGE`。

### 5.2 自用/侧载（推荐路径）

自用场景更简单：直接 `adb install -r app-release.apk`，无需过审。建议：

- 保留一份签名密钥备份（丢失则无法覆盖升级）。
- 开启系统「未知来源安装」限制仅对本应用。

## 7. 已知边界（写给自己看）

1. **Autofill 抓不全**：有的 App 用自绘控件 / Flutter / RN 自绘输入框，`AssistStructure` 里没有 `autofillId`，系统根本不会发起填充请求 —— 这类只能靠无障碍。所以双通道不是冗余，是必需。
2. **无障碍抓不到浏览器真实域名**：地址栏节点在不同浏览器差异极大，识别失败时降级为用户手填站点名，**绝不猜域名**（猜错会把密码存到错误条目上）。
3. **没有 root 就无法阻止别的无障碍应用读我们的界面**：这是 Android 的固有限制。缓解：`FLAG_SECURE` 只防截屏不防无障碍；因此解锁后密码默认遮蔽、显示 15s 自动复原、复制即清空，都是为缩短暴露窗口。
4. **主密码忘了就是真的没了**：没有后门、没有找回。这是设计选择，要在引导页讲清楚（P1 已加必勾确认）。
5. **SQLCipher 首次打开有 ~100ms 额外开销**：影响冷启动，已计入 800ms 预算。
