## 2. 为什么去掉主密码

原需求（用户原话）：

> 我这个软件是放在手机上用的，功能不用这么复杂，不需要设置密码什么的，是为了方便查看自己的账号密码或者自己记录账号密码【就像记事本一样】，不需要搞那么严格，因为只是自己用，平时账号密码也是只存放在记事本上。

这句话里有两个事实决定了设计：

1. **原始状态就是明文记事本。** 之前的加密方案不解决用户的实际问题，而是给一个原本不存在的问题加了成本（每次启动输密码、忘记即全丢）。
2. **「方便」是核心指标。** 在手机上，每一次多余点击都是真实的摩擦成本。

所以做的是**降低门槛**，不是**取消安全设计**：SQLCipher 仍在（整库文件不是裸 SQLite），字段写入仍走统一的 `FieldCrypto` 抽象，AAD 绑定逻辑仍在。变的只是密钥来源与字段是否加密。

### 代价必须写清楚

现在能读到这台手机上下面两样东西的人，就能看到全部账号密码：

- `/data/data/com.yg.vaultbook/databases/vault.db`
- `/data/data/com.yg.vaultbook/shared_prefs/simple_vault.xml`

获得这两样的途径：手机已 root、系统备份被导出、调试版被 `adb backup`、或手机本身没锁屏被人直接打开。

**这与"把密码抄在手机记事本里"完全同级** —— 没有更高，也没有更低。这正是用户明确接受的前提。

## 3. 数据现在长什么样

列名**全部没改**，仍叫 `title_ct`、`password_ct` 这类（`_ct` = ciphertext）。改列名要迁移八张表、影响所有 DAO 与既有备份文件，收益只是"名字更诚实"。

实际内容：

| 项 | 改造前 | 现在 |
|---|---|---|
| 数据库文件 | SQLCipher AES-256，口令由主密码派生 | SQLCipher AES-256，口令是随机 32 字节**明文**存在 SharedPreferences |
| 字段内容 | AES-256-GCM 密文，AAD = `entryId\|fieldName` | UTF-8 明文 |
| 打开应用 | 输主密码（PBKDF2 21 万次，约 0.2–1 秒） | 无感，直接进列表 |
| 自动锁定 | 后台 30 秒 | 无 |

`SimpleKeyStore` 里的口令为什么不明文存？因为它**只能**明文存：塞进 AndroidKeyStore 的话，用户清一次应用数据、或者换签名重装，就永久打不开自己的数据 —— 对"日常速查"来说这是比"被 root 读取"更可能发生的失败。它防的是**单独拷走 `vault.db`** 这一种情况（比如某些备份工具只备份数据库目录）。

### 打不开的两种情况

`openSimple()` 的失败面只有两个，都写在 `SimpleKeyStore` 的注释里：

1. `DbKeyMissingException` —— 库文件在、口令文件不在（用户手动删了 `shared_prefs`，或换了签名重装导致 SharedPreferences 被清）。**绝不静默新建**，否则等于把旧数据藏起来让用户以为丢了。
2. SQLCipher 打不开 —— 文件损坏，或口令与库不匹配。

界面上的 `OpenFailedScreen` 会把技术信息（异常类型 + 消息）用等宽字体显示出来，并提供「重试」与「新建一个空库」。重置有二次确认，文案提醒**先把 `databases` 与 `shared_prefs` 两个目录拷出来**。

## 4. 粘贴识别怎么做

入口是编辑页标题框上方的「从剪贴板粘贴」。识别逻辑全在 `CredentialParser`，纯函数、零 Android 依赖。

### 三步策略：先精确、后猜测

**第一步 `key: value`**。正则扫近义词表，命中就采用：

- 账号类：`登录账号`/`登录名`/`用户名`/`用户`/`账号`/`帐号`/`账户`/`手机号`/`邮箱`/`username`/`userid`/`account`/`login`/`email`/`phone`/`mobile`/`user`
- 密码类：`password`/`passwd`/`passcode`/`pwd`/`secret`/`密码`/`口令`
- 网址类：`website`/`domain`/`网址`/`网站`/`链接`/`地址`/`url`/`site`/`link`/`host`
- 标题类：`title`/`name`/`app`/`标题`/`名称`/`站点`/`应用`

**第二步找网址**。整段里搜 `https?://…`，没有再搜裸域名。裸域名要排除已被当成账号/密码的那串，避免把 `admin.com` 当站点。

**第三步按位置猜**。剩下的行：

- 只剩一行 → 按空格/`----`/`|`/`,`/`，`/`;` 切分，三个分量当（标题, 账号, 密码），两个分量当（账号, 密码），一个分量只当账号
- 剩两行 → 第一行账号、第二行密码
- 剩三行且第一行**像站点名** → 第一行当标题

`looksLikeSiteName` 的判据：长度 1–12、不含数字、不含 `@`、不含空白、含 CJK 字符。所以 `淘宝` 是站点名，`admin` 和 `13800138000` 不是。

### 一条铁律：归一化只用于定位，取值一律从原文切

密码里出现全角字符、空格、中文标点都是合法的。一旦为了识别方便去归一化文本，写进库的密码就和真实密码不一样了 —— 而这种错误**用户当场看不出来**，等他去登录才发现。

所以：比较 key 名时用小写归一化文本，取值时 `text.substring(...)` 从原文切。

### 五个踩过的坑（都有测试钉住）

| 坑 | 现象 | 修法 |
|---|---|---|
| 同一行两个 key | `账号：admin 密码：abc123` → username 成了 `admin 密码：abc123` | 值截止到下一个 key 的起点，而不是行末 |
| 残行未归一化 | 只粘 `www.taobao.com`，`url` 已归一成 `taobao.com`，这行又被当账号 | 过滤残行时两边都过 `cleanUrl` |
| 全角等号 | `账号＝alice` 认不出 | 分隔符加 `＝`(U+FF1D) |
| 纯标点 | `。、；：！！！` 被切成账号+密码 | 「账号与密码都无字母数字」时整组丢弃 |
| 长 key 被短 key 抢 | `username:` 被切成 `user` + `name:` | 正则里长 key 排前面（交替分支先到先得） |

### 不自动填入，只给建议卡

新建条目时，如果四个字段都空，会读一次剪贴板并尝试识别，然后**显示一张提示卡**（标题/账号/密码点数/网址）+ 两个按钮「忽略」「填入」。

不自动填入的理由：剪贴板里可能是与本次无关的东西（刚复制的验证码、地址、别人的账号）。自动填进去用户要手工清空，比多点一下更烦。

## 5. 其他为「方便」做的改动

| 改动 | 理由 |
|---|---|
| 详情页打开就显示密码 | 定位是"打开就要看到"。藏起来让用户再点一次「显示」，每看一条多一次点击 |
| 列表行尾加「复制」 | 最高频动作从"进详情 → 点复制 → 返回"变成一次点击 |
| 取消自动锁定 | 没有"锁定"状态了，锁了也没意义 |
| 顶栏锁图标 → 设置 | 锁图标在新模型下没有功能 |

列表行的复制仍然走 `copySecret`：写剪贴板 30 秒后，**只在内容仍是自己写入的那串时**才清空。这条保留是因为剪贴板是唯一会"漏"到别的应用的地方 —— 代价低、收益明确。

## 7. 真机验证

前置：已装 v1.3.0（`dist\账号本-1.3.0-debug.apk`）。

**首次打开（4 步）**

1. 点图标 → 应该**直接**看到列表页，没有密码框
2. 空列表显示「还没有记录 / 点右下角的 + 手动添加第一条」
3. 右下角 + → 输入标题「测试」、账号、密码 → 保存
4. 列表出现这一条，点进去**密码直接可见**

**粘贴识别（4 步）**

1. 在微信/记事本里复制一段：`账号：testuser 密码：abc123`
2. 回到应用 → + → 应该自动出现提示卡「账号 testuser / 密码 ••••••」
3. 点「填入」→ 三个字段都填好
4. 再试一次只复制 `www.taobao.com` → 提示卡应只显示网址，不显示账号

**复制按钮（2 步）**

1. 列表行尾点「复制」→ 提示已复制
2. 粘贴到微信输入框 → 是密码；等 30 秒再粘贴 → 剪贴板已空

**出问题时看哪里**

| 现象 | 先查 |
|---|---|
| 卡在「正在打开…」 | 大概 1 秒内会过；超过 5 秒是 SQLCipher 初始化异常 |
| 显示「数据打不开」 | 屏幕上有技术信息。`DbKeyMissingException` = 口令文件丢了；其它看消息 |
| 粘贴没反应 | 剪贴板为空（部分系统限制后台读剪贴板），或内容里确实没有账号密码 |
| 识别错字段 | 点「忽略」后手动填。识别只是预填，永远不覆盖已有内容 |

## 8. 已知限制

- **数据是明文**：见 §2。这是主动选择，不是疏漏。
- **口令与库文件绑在一起**：两者不能分开丢，否则打不开（`OpenFailedScreen` 的重置按钮是唯一出路）。
- **粘贴识别是启发式**：`admin` 与中文站点名之间靠"含不含数字、含不含 CJK"区分，会有误判。误判只影响预填。
- **无障碍通道没跟着改**：`CaptureAccessibilityService` 与自动填充仍在，但 `pending_captures` 的密文现在也走 `PlainFieldCrypto`（因为 `captureQueue` 的 cipher 换成了 `plainCipher`）。旧的 Keystore 密文行会解不开 —— 如果你之前装过 v1.2.0 并且有未处理的待确认捕获，那些条目会显示为空白，删掉即可。
- **`core/biometric/*` 成了死代码**：文件还在，Gateway 上仍有五个方法，但没有任何界面调用它们。留着是为了以后想恢复指纹时不用重写。
- **`UnlockScreen.kt` 已删除**，旧的主密码路径（`createVault`/`unlock`/`changeMasterPassword`）仍在 `VaultGateway` 上但无入口。如果库里是 v1.2.0 的老数据（主密码加密），本版**读不出来** —— 需要先卸载重装。
