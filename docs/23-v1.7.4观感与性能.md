# v1.7.4 观感与性能

这一版没有新功能，只解决两件事：**打开它、看它的时候更顺眼**，以及**它算得更少**。

改动的原则是「不引入新依赖、不加动效噪声、每个改动都能说出它解决了什么具体感受问题」。下面每条都按「问题 → 改法 → 为什么这么改」写。

---

## 一、冷启动不再闪白

**问题**：`AndroidManifest.xml` 里主题一直直接引用平台主题 `@android:style/Theme.DeviceDefault.Light.NoActionBar`，窗口底色是纯白。Compose 第一帧要等 Activity 起来、主题组合完成才画出来，于是：

- 白天：白底 → 米绿背景，一闪。
- **深色模式：刺眼的白闪一下，然后才变黑**，这是最难受的一条。

**改法**：

| 文件 | 内容 |
| --- | --- |
| `res/values/colors.xml` | `vault_window_background = #ECF1ED`（等于 `Theme.kt` 里 Light 的 `background`） |
| `res/values-night/colors.xml` | `vault_window_background = #0D1110`（等于 Dark 的 `background`） |
| `res/values/themes.xml` | `Theme.VaultBook`，parent 是平台浅色主题，`android:windowBackground` 指向上面的颜色 |
| `res/values-night/themes.xml` | 同上，parent 换平台深色主题 |
| `AndroidManifest.xml` | application 的 `android:theme` 改指 `@style/Theme.VaultBook` |

**踩到的坑**：`parent` 一开始写成 `Theme.DeviceDefault.Light.NoActionBar`（不带 `@android:style/` 前缀），aapt2 直接链接失败：

```
error: resource style/Theme.DeviceDefault.Light.NoActionBar
  (aka com.yg.vaultbook.debug:style/Theme.DeviceDefault.Light.NoActionBar) not found
```

原因是要引用**平台**样式必须写全 `@android:style/...`，否则会被当成"本项目里要定义一个同名父样式"。两个 `themes.xml` 都补上前缀后通过。

**为什么不用 `SplashScreen` API**：那个库要求 API 31+ 才能拿到系统级启动画面，minSdk 是 26，为 26~30 引一套兼容实现只为了盖住 200ms 的白底，不划算。窗口底色是最小代价的解法，而且深色浅色都由系统自动选。

## 二、字更"立得住"

`Theme.kt` 的字号原本偏保守，标题在列表页顶部显得不够重：

| 样式 | 原来 | 现在 |
| --- | --- | --- |
| `displaySmall`（列表大标题） | 30sp / 行高 36 / 字距 -0.5 | **34sp / 40 / -0.8** |
| `headlineSmall`（详情页标题） | 24sp / 30 / -0.3 | **26sp / 32 / -0.5** |
| `Shapes.medium` | 16dp | **18dp** |
| `Shapes.large` | 22dp | **24dp** |
| `Shapes.extraLarge` | 28dp | **30dp** |

标题放大后配合负字距（大字号下字距要收，不然汉字之间会散开），整页的层级才撑得住下面的卡片。

## 三、列表页

### 3.1 顶栏：从"三行文字 + 三个图标"变成"标题 + 状态胶囊 + 三个圆钮"

- 计数从一行灰字改成 `primaryContainer` 的胶囊（「共 12 条」/「还没有记录」），padding 横向 9dp、纵向 3dp。用处是：它现在是页面里唯一带色的元素，一眼能定位到"我有多少条"。
- 三个入口（待确认、更多、设置）原本是裸 `IconButton`，现在统一抽成 `HeaderAction`：40dp 圆形、`surfaceVariant` 60% 透明底、按压缩到 0.92。图标颜色统一 `onSurfaceVariant`。
- 抽成组件的收益不只是好看：三处图标的手感从此一定一致，以后加第四个入口不会又长出一个不一样的。

### 3.2 搜索框：胶囊改圆角矩形，加聚焦态

- `CircleShape` → `RoundedCornerShape(15.dp)`。原来那个胶囊看起来像按钮，而它其实是这页唯一的输入框。
- 描边走 `Modifier.border` 而不是 TextField 的 `indicator`：indicator 只在底部画一条线，这里要的是整圈。
- **聚焦时描边从 1dp/`outlineVariant` 变成 1.5dp/主色 55%，搜索图标同时转主色**。输入时给一个明确的"我现在在这里"的信号，比任何提示文字都直接。
- 没有写死高度：M3 的填充式输入框自带 56dp 最小高度，外面压到 50dp 会把内部装饰挤到裁切。

### 3.3 卡片：圆角 20、阴影 2、加一圈描边

`EntryRow` 的 `Card`：

```kotlin
shape = RoundedCornerShape(20.dp),
elevation = CardDefaults.cardElevation(defaultElevation = 2.dp),
border = BorderStroke(1.dp, MaterialTheme.colorScheme.outlineVariant.copy(alpha = 0.45f))
```

**为什么要"阴影 + 描边"两样都上**：深色模式下阴影几乎看不见（黑底上的黑影），卡片就没有边界了；浅色模式下描边又太抢眼。两者叠加，两套主题都能立住。

头像 46dp → 44dp，跟 20dp 的圆角配起来比例更稳（46 配 18 时头像显得略大）。

### 3.4 "复制"从文字变成按钮

原来只有「复制」两个字和一层浅绿底，右端看起来像一段说明文字。现在：

- 圆角 `RoundedCornerShape(11.dp)` + `BorderStroke(1.dp, primary.copy(alpha = 0.22f))`
- 内边距 12dp / 7dp

**试过加图标，放弃了**：`Icons.Filled.ContentCopy` 不在 `material-icons-core` 里，工程只依赖了 `material3`（core 图标集里没有这一枚）。为了一枚图标把 `material-icons-extended` 整个依赖进来，R8 虽然能裁掉未用的，但构建时间和 dex 都得付代价。改用底色 + 描边 + 圆角表达"这是按钮"，零成本。

### 3.5 列表项动画与回调稳定化

- `Modifier.animateItem()`（Compose 1.7）接在 `enterFadeSlide` 前面：新建、删除、切换筛选导致的重排会滑动到位，而不是瞬间跳。
- 每行的 `onOpen` / `onLongPress` / `onCopy` 三个 lambda 改成 `remember(entry.id) { ... }`。原先每次重组都新建闭包（`{ onOpenEntry(entry.id) }`），`EntryRow` 的参数引用每次都变，等于给组合器发了"全都变了"的信号；记忆化之后筛选/搜索时不会整屏重组。
- `contentPadding` 底部 110 → 112dp、`spacedBy` 10 → 11dp，配合 20dp 圆角让行距不显挤。

### 3.6 新建按钮：从纯色块变渐变块

`Surface` 换成 `Box` + `shadow(12.dp, clip = false)` + `clip(20.dp)` + `linearGradient(primary → primary@80%)`。

**顺序不能反**：`shadow(clip = false)` 必须在 `clip()` 之前，否则阴影会被裁掉，只剩一块没有纵深的色块。

### 3.7 筛选条

- `CircleShape` → `RoundedCornerShape(11.dp)`，跟搜索框、复制按钮统一成"圆角矩形家族"。
- 选中项加 `shadowElevation = 5.dp`，未选中保留 1dp 描边。选中态从"颜色不同"升级为"浮起来一点"。

## 四、详情页

三张卡片（账号/密码、备注与自定义字段、密码历史）统一到与列表同一口径：

```kotlin
shape = RoundedCornerShape(20.dp),
elevation = 2.dp,
border = BorderStroke(1.dp, outlineVariant.copy(alpha = 0.45f))
```

列表和详情是同一个信息的两级视图，圆角/阴影/描边不一致时，来回切换会有"换了个应用"的错觉。

## 五、性能：头像不再每帧算哈希

`EntryAvatar` 原本每次组合都做三件事：`paletteOf(seed)`（含 `hashCode()` 与取模）、`RoundedCornerShape(size * 0.30f)`、`Color.White.copy(alpha)`。滚动列表时每帧每行都重算一遍。

```kotlin
val palette = remember(seed) { paletteOf(seed) }
val shape = remember(size) { RoundedCornerShape(size * 0.30f) }
val (from, to) = palette
```

外加一圈 `BorderStroke` 效果的内描边（`Color.White.copy(alpha = 0.16f)`），把渐变块的边缘钉住 —— 深色模式下渐变贴到卡片底色时，边缘原本是"糊"的。

这一条和 3.5 的回调记忆化是同一类账：**滚动时的每帧成本**。374 项单测覆盖不到这类问题，只能靠读代码发现。

## 六、验收

```powershell
# 单测
gradle :app:testDebugUnitTest --offline      # 23 个类 / 374 项 / 0 失败
# 出包
gradle :app:assembleRelease --offline        # 7.03 MB
# 装机
adb install -r dist\账号本-1.7.4.apk
```

装到手机后建议按这条顺序看一遍（这几处正是本版改动最集中的地方）：

1. **深色模式下杀进程再打开** —— 第一帧应该是深色，不该有白闪。
2. 列表页滚动，右侧"复制"块是否一眼能认成按钮。
3. 点进搜索框，描边和放大镜是否变绿。
4. 新建一条 → 卡片是否滑动入场；删一条 → 下面的是否滑上来。
5. 详情页与列表页来回切，卡片的圆角和阴影是否一致。

## 七、这批没做的

| 项 | 为什么没做 |
| --- | --- |
| 主动画（`SplashScreen` 库） | 要 API 31+，为 26~30 引兼容实现代价大于收益 |
| 图标库 `material-icons-extended` | 只为几枚图标引入整库，构建时间与 dex 都要付钱 |
| 从 `Theme.kt` 抽 `styles.xml` 完整主题 | 现在只有窗口底色走 XML，其余全在 Compose 里；抽出去会变成两处维护同一套颜色 |
| 空状态插画重绘 | 现有 Canvas 插画（本子 + 三条记录 + 锁）够用，重绘是审美偏好不是问题 |
| 第三批功能（CSV 导入 / 备份提醒 / 安全体检） | 这是功能不是观感，单独一批做 |
