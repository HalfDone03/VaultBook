# v1.7.6：表格导入、备份提醒、安全体检

第三批功能。三条都不改数据格式，从旧版本升级上来不用迁移。

## 一、从表格导入（CSV）

以前只能导自家 `.vbc` 备份，从别处（Excel 导出的表、记事本抄的一列「平台,密码」）搬账号只能一条条手输。

现在备份页多一个「从表格导入（CSV）」：

1. 选中文件 → 解析 → **先给预览**（能读几行、识别到哪些列、前四条长什么样）→ 你点「开始导入」才真正写库。
2. 同名的跳过不覆盖；分类按表里写的名字自动建。
3. 解析在后台线程，几千行的表不会把界面卡住。

### 认列的方式

| 情况 | 怎么读 |
| --- | --- |
| 有表头 | 按列名认：平台/标题/网站/名称 → 标题；账号/用户名/手机号/邮箱 → 账号；密码/口令 → 密码；网址/链接/URL → 网址；备注/说明 → 备注；分类/分组 → 分类；两步验证/OTP/TOTP → 验证码密钥 |
| 没表头 | 按列顺序：2 列 = 平台 + 密码；3 列及以上 = 平台 / 账号 / 密码 / 网址 / 备注 / 分类 |
| 分隔符 | 逗号、制表符、分号、竖线都认（按前几行哪个出现得匀称来猜） |
| 引号 | 标准 CSV 规则：字段里可以有逗号、换行，`""` 表示一个引号 |
| 编码 | 带 BOM 的 UTF-8、不带 BOM 的 UTF-8、GBK 都试一遍 |

**为什么要严格试解码**：先按严格 UTF-8 解，失败才退 GBK，最后才用宽松 UTF-8 兜底。反过来（直接宽松解）会让 GBK 的中文静默变成一排 `�` —— 用户看不出错，等发现时已经导进库了。

**为什么表头识别要「至少命中两列」**：只命中「密码」一列时，很可能是把某一行数据当成了表头（比如有人的平台名就叫「密码」）。宁可当数据，不要当表头。

上限 8 MB，超出直接说清楚不处理 —— 表格是纯文本，8 MB 已经是几十万行。

## 二、备份提醒

- 每次导出成功记一个时间戳（独立 prefs，不写进保险库）。
- 设置页「导出加密备份」下面直接显示「今天备份过 / 3 天前备份过 / 还没备份过」。
- 30 天没备份会提一句；条目少于 5 条时不提 —— 东西还没攒起来就催备份是噪音。

为什么只记时间不记内容：这个值在保险库没解锁时也要读（列表页要判断要不要提醒），不该跟加密数据绑在一起。

## 三、安全体检

设置页新增入口，进去跑一次全库扫描：

| 检查项 | 判据 |
| --- | --- |
| 太弱的密码 | `PasswordStrength.score <= 1` |
| 重复使用的密码 | 两条以上用同一个密码（比的是 `contentHashCode`，不把密码拼成 String） |
| 很久没换的密码 | 距离上次改密码 ≥ 180 天 |
| 没存密码的条目 | 只有平台名，没有密码 |

每条都能点进对应条目去改。扫完立刻把解出来的 `CharArray` 填 0，不留明文副本。

**只给建议不自动改**：自动改密码意味着应用要替你决定新密码，而那正是用户最不想要的 —— 他可能正拿那张纸在记。体检的价值是「让你知道先动哪个」。

## 五、没做的

- **不支持 xlsx**：解析 Excel 二进制要引入 Apache POI 级别的依赖，包体翻倍不值；让用户「另存为 CSV」是一步操作。
- **不支持导出 CSV**：导出的意义是给别的软件用，而这个应用的用户场景是「自己看」。真需要的话 `.vbc` 能带走全部数据。
- **体检不做定时提醒**：扫一遍要解全部密码，常驻跑就是白烧电。
- **不自动改弱密码**：见上。
