# 1.13 · 平台名加密码整行粘在一起

## 这一版解决什么

黏贴区里出现这种一行一条、**既没有分隔符也没有账号**的写法：

```
微软账户密码Zx8Kq2Lm7V1
医保平台密码Ab@123456.
个人所得税app密码 Zx8Kq2Lm7V!
计算机网站密码密码  Zx8Kq2Lm7V!!
Cloudflare密码 Zx8Kq2Lm7V!
腾讯服务器密码Zx8Kq2Lm7V!’
```

以前这种情况一条都认不出，整段被并成一条错的：标题取自第一行、账号空着、
密码取的是别行的值。

## 为什么以前认不出

1. **字段名和值之间没有分隔符**。键值规则要求字段名后面跟冒号、等号或空白，
   `密码Zx8Kq2Lm7V1` 里两者直接贴着，规则够不着；`UNGLUED_AFTER` 只处理
   「值在前、字段名在后」的反方向。
2. **整段里没有一处能让「按位置猜」落脚**：没有逗号、竖线、制表符，
   也没有空行分段，每条记录都只有密码这一样东西。
3. **逐行分支要求账号和密码都齐**。`parseMany` 里「一行就是一条记录」的
   判断原本要求每行都凑出账号与密码，只有密码的行全部被丢在门外，
   于是退回「整段一条」的兜底，结论是错的那一条。

## 改了什么

- 新增一条逐行分支：整段里没有任何冒号或等号、且每一行都能单独认出密码时，
  一行就是一条记录（不再要求有账号）。放在「按位置猜」之前，
  避免整段并成一条。
- 表格按两列切时，若第一格以「密码／口令／账号」收尾
  （`计算机网站密码密码  Zx8Kq2Lm7V!!`），不再强行切成「账号 密码」——
  那会凭空造出一个账号。
- 位置猜出来的账号若只是「标题后面再接一个字段名」，判为没有账号。
- 原文里同一个字段名连写两遍时，标题只留前一半（`计算机网站密码密码` → `计算机网站`）。

## 现在的识别结果

上面六行分别认成：微软账户 / 医保平台 / 个人所得税app / 计算机网站 /
Cloudflare / 腾讯服务器，各带一个密码、账号留空，六条互不串行。

## 验证

- 语料表新增一组七条同形状样本（值全部编造），总数四百五十九条。
- 三十个测试类、五百零一例、零失败。

## 仍然不认的

- 同一行里先写平台名、再写「密码」、然后又写「账号」的交错写法
  （`淘宝密码Xyz123账号tb_1`）——账号那边的边界无法与密码值区分。
- 值为纯中文且不含任何半角字符的行（`密码：记住我了`）按说明处理，不当凭据。
- 一行里出现两个不同的平台名、且都没有分隔符的行，仍按一条处理。
- 平台名与密码之间夹着备注短语、又没有标点的行（`微软账户备注家里用密码Xyz123`）。
- 值里带空格的行（`密码：Zx8Kq 2Lm7V`）密码会被空格截断，需要在应用里手动改。
