# 1.10：先写一张粘贴样本表，再让解析器去够

## 起因

1.9 修的是用户当场给的六段样本。六段都过了，但那只证明这六段能过，不证明别的抄法能过。用户的原话是「你多生成点规则，然后自测，识别不了的继续优化」。

所以这一版换了做法：不先写规则，先写一张「这段文字应该被认成什么」的表，让表来决定还缺什么规则。

## 做法

新建 `CredentialParserCorpusTest`，`Case(名字, 粘贴内容, 期望的若干条)`，用 `parseMany` 逐条比对标题 / 账号 / 密码 / 备注。一条对不上不影响其他条，全部不符收集起来一次报出，避免「改一条、跑一遍、发现下一条」。

表按「手上真会粘到的东西」分组，不按规则分组：

一、一行一个字段；二、同一行几个字段；三、`标签:账号:密码` 三格；四、列表符号（`-`、`•`、`1.`、`①`）；五、表格（有表头、无表头、带序号列、制表符、竖线）；六、JSON（数组、外套 `data.list`、单条多层、数字密码、转义引号）；七、XML（标签、包裹一层、属性、单引号属性）；八、网址（查询串、带端口、userinfo、粘贴整段链接）；九、中文句子（「淘宝的账号是… 密码是…」、连写、书名号、方头卡片）；十、从别的软件复制出来的（YAML 列表、带 BOM 的 CSV、引号包住的逗号、全角空格）；十一、账号密码上下交替；十二、别名写法（`账号1：`、`初始密码：`、字段顺序打乱、`ACCOUNT=x&PASSWORD=y`）；十三、残角（只有密码、只有网址、备注里带冒号、尾行一句提醒）。

样本里的值全部是编造的假数据，真实样本只借形状。

## 补了哪些规则

按失败顺序：

- 字段名后面跟序号：`账号1：`、`密码2：`。字段名与分隔符之间允许最多三位数字。
- 全角竖线 `｜` 当分隔符（表格、三格行都认）。
- 三格行支持竖线与「平台：账号 / 密码」两种写法。
- 中文引号与直角引号包住的值去壳：`“taobao_48”`、`「淘宝」`。
- 列表符号与序号：`-`、`•`、`·`、`▪`、`①`、`第3条`。
- 方头卡片 `【淘宝】` 当标题。
- 环境变量写法：`SITE=github`、`ACCOUNT=ac&PASSWORD=pw`。
- 查询串：值取到第一个 `&` 为止（只有当 `&` 后面还是 `键=值` 时才切）。
- 中文句子里的「的」「是」「为」与字段名尾巴剥掉，`淘宝的账号是 taobao_12` 不再把整句当标题。
- 账号密码连写里抠账号：`微博账号weibo_13密码Wb@131313`。
- 上下交替支持三行版（标题 + 账号 + 密码），英文站名当标题也认。
- 冒号链与键值的优先级：字段名自己就能凑出账号和密码时不让链式抢走（`账号：a1，密码：b1`）。
- 无表头但行首是列名、混用分隔符（分号 / 竖线 / 逗号 / 制表符 / `&`）的行内记录。

## 刻意收住的

- 纯汉字的两段不当账号密码（`项目,说明` 这种是表头或说明）。
- 括号里只有占位说明（`平台(必填) 账号(必填)`）不认成凭据。
- 英文里带数字的串不当平台名（那是账号，不是站名）。
- 值结尾碰巧是「账号」「密码」两个字的，不砍（备注写着「老账号」得原样留着）；只剥「分隔符 + 字段名」那种粘法。
- 三行交替要求第三行真的像密码，四行以上才做整段交替，避免把普通三行散文拆成账号密码。

## 验证

30 个测试类、501 个用例，0 失败；语料表本身 97 条全过。

出包：`dist/VaultBook-1.10.apk`，7.07 MB，最小系统 8.0，只带 arm64，versionCode 200。

## 还没做

- 嵌套很深的 XML（带命名空间、带属性包裹）仍不认。
- 一条里既有账号密码又有手机验证码时，验证码会被当成密码。
- 一行里出现两组以上「账号 + 密码」时只认第一组。
