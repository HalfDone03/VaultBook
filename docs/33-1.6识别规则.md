# 1.6 粘贴识别规则扩充

## 1. 起因

老爹的反馈是「粘贴识别的规则多加点」。上一版（1.4）只认四种形状：一行一条、空行分段、重复 `密码` 键切块、连写（汉字与英文交界处切）。日常能遇到的抄法远不止这些——记事本里手抄常常不打冒号，从表格复制会带表头，网上抄来的笔记常带序号和横线分隔，还有人把备注也一起粘进来。这些形状落到旧解析器上，结果就是「标题认不出、账号被吞了一整行」。

这一版的目标不是把 AI 塞进来，而是把**能枚举的抄法**补全，让常见形状都能拆对。

## 2. 新增的规则

| 形状 | 例子 | 认出什么 |
|---|---|---|
| 空白分隔的键值 | `用户名 admin` + `密码 abc123` | 账号 admin、密码 abc123 |
| 键值同行空白分隔 | `账号 admin 密码 abc123` | 同上 |
| 键名独占一行 | `密码` 换行 `abc123` | 密码 abc123 |
| 一行里的英文键 | `username admin` / `PASSWORD 123456` | 按键名归类 |
| 账号密码用一个冒号 | `zhang@qq.com:abc123` | 账号 zhang@qq.com、密码 abc123 |
| 链接里的 user:pass | `https://alice:pw@b.com/x` | 账号 alice、密码 pw、网址 b.com |
| 整行横线分段 | `---` / `===` / `***` / `———` | 当成多条记录的分界 |
| 行首序号 | `1. ` `2、` `(3)` `①` `第4条` | 剥掉序号再解析（`1.5` 这种小数不动） |
| 表头行 | `平台 账号 密码` | 识别为表头丢弃，不当记录 |
| 备注行 | `备注：备用密码在邮箱里` | 整行吃掉，不当凭据 |
| 两行、首行是平台名 | `淘宝` 换行 `abc123` | 标题淘宝、密码 abc123 |
| 行里混着网址 | `admin abc123 www.taobao.com` | 网址单独拿出来，不当密码 |
| 连写里带账号标签 | `账号admin密码abc123` | 账号 admin、密码 abc123 |
| 平台名和账号贴在一起 | `抖音12313213 1231313` | 标题抖音、账号 12313213、密码 1231313 |
| 两段且首段是平台名 | `抖音 12313213` | 标题抖音、账号 12313213（不是「账号抖音」） |

字段名表扩到五组：账号类、密码类、网址类、标题类、忽略类（备注/说明/序号/分类/类型/标签）。忽略类是这一版新加的——它是「认得出但不算凭据」的字段，作用是把这类行消化掉，否则 `备注：备用密码在邮箱里` 会被记成「账号叫备注、密码叫备用密码在邮箱里」。

## 3. 几条刻意的取舍

**长的字段名排前面。** 正则的交替分支是「先匹配到的赢」，`user` 若排在 `username` 前面，`username:` 会被切成 `user` + `name:`。同理 `用户名` 必须排在 `用户` 前面。这一条在代码注释里也写着，改字段表时别打乱。

**空白分隔要卡边界。** `BARE_KV_REGEX` 要求键名前面是行首或空白/中文标点，否则 `我的密码` 里的「密码」也会被当成键名。

**空行分段加了一道闸。** 原来只要出现空行就切块，于是

```
账号：admin

密码：abc123
```

会被掰成「只有账号」和「只有密码」两条。现在要求每一块都带密码才按空行切，否则退回单条记录处理。

**序号只在行首剥。** `1.5`、`3.14` 这种小数不能被当成序号，所以序号后面若紧跟数字就不认。

**表头判定要整行都是表头词。** 2 到 6 个词、且每个词都在表头词表里才判为表头。`淘宝 账号 密码` 里「淘宝」不在词表，所以不当表头。

**备注行只吃整行。** 值是「到行尾」，不做跨行合并——跨行合并容易把下一条记录吞掉。

**位置猜错时给人一条退路。** 启发式再聪明也判不出 `抖音 abc123` 里谁是谁——只有用户知道。所以「认出这一条」卡片上加了一个「账号密码反了？」的按钮，点一下把账号和密码对调，再点回原样；「填入表单」用的是对调后的结果。这一条是老爹提的原话：「假如识别反了，可以添加一个切换的按钮之类的」。

**平台名和账号贴在一起要拆开。** `抖音12313213 1231313` 按列拆成两段后，第一段整串会被当成账号，用户看到的就是「账号认成了抖音12313213」。平台名几乎不带数字、值几乎都带，所以「左半纯中文短词（2–6 个汉字）、右半带数字」就能安全拆。两段的 `抖音 12313213` 同理：首段是纯中文短词且次段带数字时，首段按标题理解，不按账号。

## 4. 用例

`CredentialParserTest` 新增 17 例，覆盖上表每一行形状，并有一条专门钉住「空行拆一条记录时不算两条」、一条钉住「备注行不参与识别」、两条钉住账号密码对调（含单边为空的情形）。原有的 441 例全部保留，其中 `用户 key 当账号` 在这一轮暴露了一个疏漏（字段表里只有 `用户名` 没有 `用户`），已补。

数据一律用编造的示例：`admin`、`abc123`、`p@ssw0rd`、`淘宝`、`京东`。真实账号密码绝不进测试、文档和界面文案——1.4 曾在这上面出过一次事故，见 docs/31。

## 5. 结果

- 测试：27 个类、458 个用例、0 失败（较 1.5 增 17 例）。
- 版本：1.6，versionCode 160。
- 产物：`dist/VaultBook-1.6.apk`，只含 `arm64-v8a`。

## 6. 还没做的

本机没有模拟器，`adb devices` 一直是空的，所以**这些规则只在单元测试里验过**。真机上要盯的是两件事：一是键盘弹起后粘贴框还剩几行可见（`minLines = 3`、`maxLines = 7`）；二是一次粘十条以上时预览列表的滚动与「批量存入」按钮是否仍可点。规则本身的边界情形都写在用例里，回归有据可查。
