# v1.7.2 体验修复说明

> 版本：v1.7.2（versionCode 12）　｜　一句话：**修掉五处"用起来会硌一下"的地方，包体从 10.89 MB 降到 7.03 MB。**
>
> 这一轮的来源不是新功能，而是把 v1.7.1 的代码整体过一遍，挑出**已经错、但还没被人踩到**的地方。分四批，本文件只记第一批。

---

## 1 为什么先修这五处

判断标准只有一条：**普通用户日常路径上会真的撞到，且撞到之后没法自己绕过。**

| # | 问题 | 用户看到的样子 | 为什么不能忍 |
|---|---|---|---|
| 1 | 分类改名后筛选条不刷新 | 把"工作"改成"公司"，回到列表页顶部筛选条还写着"工作"，点进去又是对的 | 只能杀进程重开。数据没错，但界面在说谎 |
| 2 | 剪贴板 30 秒清理会失效 | 复制密码 → 把应用从最近任务划掉 → 30 秒后剪贴板里**密码还在** | 这个功能存在的唯一意义就是"别把密码留在剪贴板"，失效等于没有 |
| 3 | 转屏/切深色回退到列表页 | 在详情页转一下手机，回到列表页；填了一半的新建页直接空 | 一不小心就丢输入 |
| 4 | 两条无用权限 | 安装时的权限清单里躺着「使用生物识别」「拥有完全的网络访问权限」 | 一个账号本说自己不联网，却又申请联网权限，纯属自己给自己找质疑 |
| 5 | 32 位 ABI 还在包里 | 包里两份 `.so`，手机上只会加载一份 | 白占 3.86 MB |

## 2 逐条改法与理由

### 2.1 分类筛选条改为 Flow 订阅

**原来错在哪**

```kotlin
// EntryListScreen.kt（改前）
LaunchedEffect(items.size) {                     // ← 键是"条目数"
    categories = repo.categories()
}
```

`categories()` 是一次性挂起查询。副作用键写成 `items.size`，含义变成"**只有条目数量变了才重新取分类**"。分类改名、新建空分类、删除空分类，条目数一个不动 → 效应不重跑 → 筛选条继续显示旧快照。

**改法**

```kotlin
// VaultRepository.kt
fun observeCategories(): Flow<List<PlainCategory>> =
    db.categoryDao().observeAll()
        .map { rows -> rows.map { toPlainCategory(it) } }
        .flowOn(Dispatchers.Default)

// EntryListScreen.kt
val categories by remember(repo) { repo.observeCategories() }
    .collectAsState(initial = emptyList<PlainCategory>())
```

**为什么是 Flow 而不是"把键改成 categories 的版本号"**：`categories` 自己就是被赋值的对象，拿它当 `LaunchedEffect` 的键会形成自触发循环；再引入一个手写版本号，等于把状态同步问题从 Compose 挪到自己的变量里，只是换了个地方错。数据库是唯一真源，直接订阅它。

`flowOn(Dispatchers.Default)` 必须加：`toPlainCategory` 要解密分类名（AES-GCM），放主线程是白白占用帧预算。

### 2.2 剪贴板清理改成「落盘 + 前台补清」

**原来错在哪**

```kotlin
// ClipboardSupport.kt（改前）
private val mainHandler = Handler(Looper.getMainLooper())
mainHandler.postDelayed({ clearIfStillOurs(value) }, 30_000)
```

`postDelayed` 挂在**进程的**主线程消息队列上。用户把应用从最近任务划掉、系统因内存压力回收进程，队列随之消失 —— 30 秒后什么都不会发生，密码在剪贴板里躺到用户自己复制别的东西为止。而"复制完就退出应用"恰恰是这个 App 最常见的用法。

**改法**

1. 复制时把**内容的 SHA-256**（不是明文）与到期时间写进 `SharedPreferences("clip_guard")`；
2. 仍然 `postDelayed` 一次（进程活着时最准时）；
3. `MainActivity.onResume()` 调 `purgeSecretClip(context)` —— 进程被杀过、用户又打开应用时，第一帧就补做清理；
4. 清理前先比 `currentClipText()` 的 SHA-256 与落盘值是否一致，只清自己写进去的那份。

**几个刻意的取舍**

- **只存 hash 不存明文**：这个 prefs 文件本身是明文可读的，存明文等于把密码复制到第二个地方，比留在剪贴板更糟；
- **后台清不掉就留记录**：Android 10+ 后台应用读剪贴板返回 null（不是空字符串）。读不到 ≠ 已经清掉，所以保留记录，等下次前台再试，而不是"尝试过一次就打死"；
- **延后 1 秒**：`TTL + 1_000`，避免与用户刚触发的复制在同一条时间线上抢跑；
- **Android 13+ 加 `ClipDescription.EXTRA_IS_SENSITIVE`**：系统自带的剪贴板浮层会把内容打码成「敏感内容」预览，这是原来完全没设的。

### 2.3 重建不丢页面：`rememberSaveable` + 三个 `Saver`

**原来错在哪**

`VaultApp.kt` 的 `screen` 与 `EntryListScreen` 的 `query` / `filter` 都在 `remember` 里。`remember` 只能活过重组，活不过 `Activity` 重建（转屏、切深色、字体大小变化、进程被回收后恢复）。

**改法**

```kotlin
private val ScreenSaver: Saver<Screen, Any> = listSaver(
    save = { ... },   // 只存能表达的字段
    restore = { ... }
)
var screen by rememberSaveable(stateSaver = ScreenSaver) { mutableStateOf<Screen>(Screen.List) }
```

三个 `Saver` 分别覆盖页面栈（`Screen`）、搜索词（String，自动）、筛选（`QuickFilter`，手写 `listSaver`，编码成 `all` / `fav` / `none` / `cat:<id>`）。

**边界判断**

- `Screen.Detail` 存 `entryId` + `reloadKey`；`Screen.Edit` 存 `entryId` + `fromDetail`。**`autoCopy` 不持久化** —— 重建后自动再复制一次密码属于"重建带来的副作用"，宁可不做；
- `MainActivity` 的六个字段（`openPendingSignal` / `sharedText` / `deepLinkTarget` / `deepLinkSignal` / `copyEntryId` / `copySignal`）**刻意不持久化**：它们是一次性触发信号，本来就在 `handleIntent()` 末尾清空；存下来只会在重建时重放，等于让"从分享进入"在转屏后再弹一次。

### 2.4 删掉两条权限

| 权限 | 为什么删 |
|---|---|
| `USE_BIOMETRIC` | v1.7.0 已把指纹整套删掉（依赖、`BiometricPrompt` 调用、Gateway 里五个方法都没了），权限声明忘了跟着删 |
| `INTERNET` | 全项目没有任何网络代码。不声明它，"这个账号本不联网"就从一句承诺变成**系统可核验的事实**（安装页的权限清单里看不到这一条） |

**将来做弱口令在线比对（HIBP）时要加回来**：那是真正需要联网的功能，届时单独加、并在设置里做成显式开关。

### 2.5 只留 `arm64-v8a`

```kotlin
ndk { abiFilters += listOf("arm64-v8a") }   // 原本是 arm64-v8a + armeabi-v7a
```

`libsqlcipher.so` 每个 ABI 一份，一份约 3.86 MB，而手机上只会加载其中一个。代价是 2017 年以前的 32 位机装不上（`minSdk 26` 的机器里这部分占比已经很低）。要照顾老机时把 `"armeabi-v7a"` 加回列表即可。

## 4 附带发现：aapt2 在"低完整性标签"的目录里无法写文件

这一轮真正卡住施工的不是代码，是构建。记录在这里，因为**重装 SDK 后可能复现**。

**现象**：`:app:processDebugResources` 恒失败，报

```
AAPT: <...>\stableIds.txt: error: failed to open: 数据无效。 (13)
```

同时还有一条误导性报错 `Failed to stat file ...\android-35\android.jar: No such file or directory` —— 而那个 `android.jar` 完好无损（27 MB）。

**排查路径**：清 `app/build`、`--no-build-cache --rerun-tasks`、把工程复制到纯 ASCII 路径 —— 全部无效。直接调 `aapt2 compile`，连最小用例都报同一个错；而它能**读**（`aapt2 dump badging` 正常）。换成 `certutil` / `copy` / `7za` 写同一个目录，全部成功 —— 说明不是杀软、不是沙箱、不是文件系统。

**根因**：

```
icacls <sdk>\build-tools\35.0.0\aapt2.exe
  → Mandatory Label\Low Mandatory Level:(I)(NW)
```

SDK 里的可执行文件带了 **Low 完整性标签**。从低完整性镜像启动的进程，写中等完整性目录时被 Windows 完整性机制直接拒绝，`aapt2` 把这个失败包装成"数据无效 (13)"。

**修法**：

```powershell
icacls '<sdk 路径>' /setintegritylevel Medium /T /C
```

（另需处理 Gradle 缓存里的两份 `aapt2.exe`。）修完 `aapt2 compile` 立即正常，`assembleDebug` 33 秒通过。
