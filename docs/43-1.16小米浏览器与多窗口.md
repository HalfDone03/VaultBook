# 1.16 · 小米浏览器抓不到，以及"网页在另一个窗口"这件事

## 反馈

开了无障碍，在小米浏览器里登录，什么都抓不到。此前夸克那条已经修好（标题不再记成浏览器名），小米这只仍然不行。

## 三条原因

### 一、网页内容根本不在活动窗口里

无障碍服务只读 `rootInActiveWindow`。很多定制 ROM 的浏览器（小米浏览器、部分 WebView 容器）把网页放在**另一个窗口**里，活动窗口只有它自己的工具栏和标签栏。于是拍平出来的节点树里没有账号框、没有密码框，`detect` 返回的表单是空的，`capture` 第一句 `if (password.isNullOrEmpty()) return false` 直接退出——表现为"开了无障碍但一条都不抓"。

这不是识别规则的问题，是**读错了窗口**。

### 二、浏览器认不出来，标题又退回工具栏

1.15 的浏览器判断只看包名白名单。小米/红米自带的那只 App 名字就叫「浏览器」，包名在不在表里取决于 ROM 版本，漏一个就整条链路退回旧行为：标题取"最浅的文本节点"，拿到的是工具栏上的字。

### 三、深度门槛是写死的

1.15 用 `depth >= 4` 找网页正文。这个数字是照 Chrome 的树估的；小米浏览器把整棵树压得更平，门槛一卡，候选集直接空掉，退回全树又拿到工具栏。

## 改法

1. **读所有窗口。** `readWindowNodes()` 遍历 `windows`，每个窗口各拍平一份；选哪一份来识别有优先级：含可见密码框的窗口 → 含任意可编辑框的窗口 → 第一个窗口。全部窗口都读失败才退回 `rootInActiveWindow`（老行为）。单个窗口读坏只跳过它，不影响其它窗口。
2. **浏览器按应用名兜底。** 新增 `BrowserHosts.looksLikeBrowserLabel()`：应用名里带「浏览器」或「browser」就算浏览器。`readForm` 与 `capture` 都改走 `isBrowserLike(pkg)`（白名单 ∪ 应用名），白名单另外补了 `com.mi.globalbrowser`。判错的代价只是"标题怎么取"，不会写错站点键。
3. **深度门槛改成自适应。** 不再写死 4，而是先看这棵树里"浏览器自己的界面"（应用名 + 工具栏占位字）最深停在第几层，取比它更深的那批当候选；一个都没有才退回全树。

## 识别结果

浏览器里：网页标题 → 记录标题，域名认不出时不拿浏览器包名当站点键（1.15 的规矩不变），标题为空也不丢这条记录（站点身份那一项按"浏览器 + 有正文"计）。

网页在独立窗口里：密码框、账号框、提交按钮都能读到，与同窗口时一致。

## 验证

- 新增两条识别层用例：树被压得很浅（正文标题在第 2 层、工具栏在第 0–1 层）仍能取到「QQ邮箱」；工具栏文案全被排除时标题留空但密码照抓。
- 30 个测试类 508 例 0 失败（较 1.15 多 2 例）。

## 仍不认 / 仍验不了

- 小米浏览器的真实层级没在真机上取过，`depth` 到底压到几层仍是估的；改成自适应后对层级不敏感，但"浏览器界面最深一层"这个基准仍可能取错（比如网页正文里恰好有一行文字与工具栏文案相同）。
- 部分 ROM 把网页放在**独立进程**，无障碍可能连窗口列表都拿不到；那种情况仍然抓不到，只能等真机反馈。
- 一段自由叙述里夹的账号密码、只有密码没有平台名、每行列顺序都不同的无表头表、密码本身含「账号/密码」字样、一行两个平台名且无分隔符、备注里再夹括号长句、值里有换行、图片文字。
