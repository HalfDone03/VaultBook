# 05 · 工程骨架说明（W0）

> 这一版的目标不是「能用的密码本」，而是**把最容易出错的地基先钉死**：
> 加密链路、密钥生命周期、两个系统服务的骨架、以及一套能自动跑的单元测试。
> UI 只有一页自检，属于刻意的最小化。

---

## 1. 怎么打开和编译

### 1.1 前置条件

| 项 | 要求 |
| --- | --- |
| Android Studio | Ladybug (2024.2.1) 或更新 |
| JDK | 17（AS 内置的 JBR 17 即可） |
| Gradle | 8.9（已写在 `gradle/wrapper/gradle-wrapper.properties`，AS 会自动下载） |
| Android SDK | compileSdk 35、build-tools 35.x、Platform 35 |
| 设备 | Android 8.0 (API 26) 及以上真机；模拟器也可跑自检 |

### 1.2 首次打开

1. Android Studio → **Open** → 选择 `账号本` 目录（选到含 `settings.gradle.kts` 的那一层）。
2. 首次 Sync 会自动下载 AGP 8.7.2 / Kotlin 2.0.21 / Compose BOM 2024.10.00，约 2–5 分钟。
3. 如果提示缺少 SDK，按提示安装 **Android 15 (API 35)** 平台。
4. `local.properties` 由 AS 自动生成，仓库里只放了 `local.properties.example` 作参考。

> 仓库里**没有** `gradlew` / `gradlew.bat` / `gradle-wrapper.jar` 这三个二进制文件。
> AS 通过 Gradle Tooling API 直接读 `gradle-wrapper.properties` 就行了，不影响使用。
> 如果你要在命令行构建，先在 AS 里跑一次 Sync，或执行 `gradle wrapper` 生成它们。

### 1.3 跑起来

```
app 模块 → Run → 选择设备
```

首屏会看到「运行加密自检」按钮。点一下，它会在**你这台设备上**真实跑完：

```
PBKDF2-HMAC-SHA256 派生 → 生成 DEK + dbKey → AES-GCM 字段加解密
→ 密文跨字段搬运必须失败 → 同一明文两次密文必须不同
→ 改主密码后 DEK 必须不变、旧密码必须失效 → 设备密钥包裹/解封
```

全部打勾说明密码学链路在真机上没问题。**任何一项失败都不要往下写业务代码**，
先排查 ROM 问题（见 §6）。

### 1.4 跑单元测试

命令行（AS 已生成 wrapper 后）：

```bash
./gradlew :app:testDebugUnitTest
```

或在 AS 里右键 `app/src/test` → Run 'Tests in ...'。

预期：**79 个测试全绿**，全程约 2–4 秒（测试把 KDF 迭代降到 1000 次，
生产默认 210000 次，只在真机自检里跑）。

## 3. 加密链路在代码里的走法

对照 `docs/02` §3 的四层结构，每一层都落到一个具体函数：

```
用户输入主密码 (CharArray)
    │
    ├─ Kdf.derive(password, params) ───────────► KEK_master (32B)     [Kdf.kt]
    │                                              │
    │                         Aead.open/​seal ─────┤
    │                                              ▼
    │                                        DEK (32B)                [KeyManager.kt]
    │                                              │
    │                         Aead.open/​seal ─────┤
    │                                              ▼
    │                                        dbKey (32B)  ──► SQLCipher 口令（W1）
    │                                              │
    └─ VaultSession.unlock(keys) ──────────────────┘
                                                   │
                                                   ▼
                              FieldCipher(dek) ──► 每条记录的每个字段
                                                   │
                                      CryptoBlob 格式落库
```

关键对应关系：

| 文档概念 | 代码 | 说明 |
| --- | --- | --- |
| 主密码 → KEK | `Kdf.derive()` | PBKDF2-HMAC-SHA256，210k 次迭代 |
| KEK 包裹 DEK | `Aead.seal(kek, CryptoAad.DEK_MASTER, dek)` | 存在 `vault_meta.wrapped_dek_master` |
| DEK 解封 dbKey | `Aead.open(dek, CryptoAad.DB_KEY, ...)` | 存在 `vault_meta.wrapped_db_key` |
| 密码正确性校验 | `masterVerifier` + `verifyMarker()` | 常量时间比较 `MessageDigest.isEqual` |
| 字段加密 | `FieldCipher.encrypt(entryId, fieldName, chars)` | AAD = `entryId|fieldName` |
| 密文包格式 | `CryptoBlob.pack()` | `version|flags|iv|ciphertext|tag` |
| 全局锁定状态 | `VaultSession.state` | `StateFlow<VaultState>` |

### 3.1 三个必须守住的不变量

代码里用注释和测试双重固定，改动时请勿破坏：

1. **DEK 永不改变**。改主密码只重算 KEK 并重新包裹 DEK → 几万条数据改密码也是毫秒级。
   见 `KeyManagerTest.改主密码保持 DEK 与 dbKey 不变`。
2. **每次加密都用新的随机 IV**。GCM 下 IV 重用 = 机密性与完整性同时崩。
   见 `CryptoBlobTest.同一明文两次加密得到不同密文`。
3. **AAD 必须绑定 `entryId|fieldName`**。否则攻击者可以把 A 账号的密码密文搬到 B 账号。
   见 `FieldCipherTest.密文不能搬到同一条目的另一个字段`。

## 4. 这一版**故意没做**的东西

| 缺失项 | 为什么现在不做 |
| --- | --- |
| Room + SQLCipher 实体与 DAO | 表结构一旦定错，后患无穷。等加密层自检在你真机上通过后，W1 一次性写好并用 `exportSchema` 落基线 |
| 依赖注入（Hilt） | 现在只有 8 个类，手工 new 更清楚。W2 引入 Hilt 时代码量已经稳定，迁移成本低 |
| 自动填充匹配引擎 | 需要真实站点样本才能调阈值。空实现是**安全默认**：返回 `null` 不泄漏「库里有没有这个站」 |
| 无障碍节点树扫描 | 同上，且必须先在多个 App 上采样节点结构 |
| 生物识别（Keystore 包裹） | `KeyWrapper` 接口已留好，W2 加 `KeystoreKeyWrapper` 即可，不动上层 |
| 主界面 / 列表 / 详情 / 生成器 | W4–W5 |
| 应用图标 | 现在用系统默认图标。上架前用 `Image Asset` 生成 |

`app/build.gradle.kts` 里这些依赖**已经写好但被注释掉**，注释里标了「W1 后半 / W2」。
要启用时取消注释，**同时确认 KSP 版本与 Kotlin 2.0.21 匹配**（`2.0.21-1.0.25`），
版本不一致 KSP 会直接报错。

## 5. 安全相关的默认设置（已生效）

| 设置 | 位置 | 原因 |
| --- | --- | --- |
| `android:allowBackup="false"` | Manifest | 绝不让保险库随系统云备份离开本机 |
| `dataExtractionRules` 全域排除 | `res/xml/data_extraction_rules.xml` | API 31+ 双保险 |
| `android:usesCleartextTraffic="false"` | Manifest | 只允许 HTTPS |
| release 开 `minifyEnabled` + `shrinkResources` | `app/build.gradle.kts` | 减小体积、混淆类名 |
| release 移除 `Log.v/d/i` | `proguard-rules.pro` | 防止日志泄漏敏感串 |
| `canPerformGestures="false"` | `accessibility_service_config.xml` | 无障碍服务只读，不模拟点击 |
| 密码走 `CharArray`，不走 `String` | `Utf8.kt` / `FieldCipher.kt` | String 驻留堆中无法主动擦除 |
| 密钥用完 `fill(0)` | `VaultKeys.destroy()` 等 | 缩短密钥内存寿命 |

## 6. 真机上可能踩的坑

### 6.1 自检项失败

| 现象 | 可能原因 | 处置 |
| --- | --- | --- |
| `PBKDF2 派生` 抛 `NoSuchAlgorithmException` | 极旧或裁剪 ROM 缺 `PBKDF2WithHmacSHA256` | 该机型不支持，降级到 `PBKDF2WithHmacSHA1` 会削弱安全性，不如放弃该机型 |
| 自检耗时 > 3 秒 | 低端 CPU | 正常。210k 次迭代在骁龙 4xx 上约 0.5–1.5s，自检里跑了多次 |
| `改主密码` 项失败且提示「DEK 被改变」 | 有人改坏了 `changeMasterPassword` | 立即回滚，这是致命错误 |

### 6.2 服务不生效

| 现象 | 处置 |
| --- | --- |
| 设置里找不到「账号本」的自动填充服务 | 检查是否装在 `debug` 变体（`applicationIdSuffix=".debug"`），部分 ROM 会隐藏带后缀的服务；用 release 包验证 |
| 无障碍服务开了但没反应 | 正常，W0 是空实现，只打日志。用 `adb logcat -s VaultCapture` 确认真机上 `onServiceConnected` 有没有来 |
| 华为/小米/OPPO 后台被杀 | 需要用户手动加白名单。`docs/04` §5 有逐 ROM 适配清单 |

### 6.3 构建失败

| 报错 | 处置 |
| --- | --- |
| `Unsupported class file major version` | JDK 版本不对，切到 JDK 17 |
| `Manifest merger failed: android:dataExtractionRules` | compileSdk 低于 31；本项目是 35，应不会出现 |
| KSP 报版本不匹配 | 见 §4 最后一段 |
