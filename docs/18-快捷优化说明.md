# 18 · 快捷优化（v1.5.0）

目标：**减少"查一条密码"的点击次数**。

改动前的主路径是「打开 → 列表 → 滑/搜 → 点进详情 → 找那一行的复制按钮」，
五步。而且列表排序用的是「最后修改时间」——每天要查的那几个站，
因为从没改过，永远沉在下面；昨天随手记的一条倒排在最顶上。

---

## 1. 列表按"用过"排序

`EntryDao.observeActive()` 的 `ORDER BY` 从 `updated_at DESC` 改成三级：

```sql
ORDER BY favorite DESC, COALESCE(last_used_at, 0) DESC, updated_at DESC
```

| 级别 | 字段 | 给用户的感觉 |
|---|---|---|
| 1 | `favorite DESC` | 星标过的钉在最上面，这是唯一能手动控制位置的东西 |
| 2 | `last_used_at DESC` | 刚查过的自己浮上来 |
| 3 | `updated_at DESC` | 都没用过时，新建/改过的在前 |

`COALESCE` 是因为 `last_used_at` 可空。SQLite 里 `NULL` 排序本来就是最小值、
会排到最后，效果一样；显式写 `0` 让意图可读，也不依赖版本行为。

### 一个必须先修的坑：`markUsed` 从来没被调用过

`VaultRepository.markUsed()` 与 `EntryDao.markUsed()` 在 W1 就写好了，
但全工程没有一处调用 —— `last_used_at` 永远是 `null`、`use_count` 永远是 `0`。
如果只改排序，这一级等于完全失效。

现在三处补上：

| 位置 | 时机 |
|---|---|
| `EntryDetailScreen` 的 `LaunchedEffect` | 打开详情 |
| `EntryListScreen.copyPassword()` | 行尾复制密码 |
| `EntryListScreen.copyUsername()` | 长按动作单复制账号 |

### 另一个坑：新建/编辑完的条目录不在第一屏

`createEntry` 原本不设 `lastUsedAt`，新建完回到列表，它按 `updated_at` 排在
所有"用过的"记录后面 —— 用户刚保存完却找不到，会以为没存上。

现在 `createEntry` 写 `lastUsedAt = now, useCount = 1`，
`updateEntry` 的 `copy(...)` 里也补 `lastUsedAt = now`：
新建和编辑本质上都是"我马上要用它"。

## 2. 长按条目 → 底部动作单

不点进详情就能完成五个动作：复制密码 / 复制账号 / 查看详情 / 编辑 / 移到回收站。

用 `combinedClickable(onClick, onLongClick)`，动作单用 `ModalBottomSheet`
而不是 `DropdownMenu`，原因是下拉菜单会跟着行滚动漂移，而且只能显示在
被点的那一行旁边 —— 一行正好在屏幕最底部时会被挤到看不见。

`ActionRow` 单独抽成一个 composable：五行里只有「移到回收站」是危险的，
需要单独 `error` 色。混在一个 `forEach` 里迟早会漏掉这个区分。

禁用态也做了：没密码时「复制密码」灰掉、没账号时「复制账号」灰掉 ——
比隐藏好，用户能看出"这条没有密码"，而不是疑惑菜单为什么少了一项。

## 3. 详情页底部常驻「复制密码」

原来要滚到密码那一行、再找右侧那个小「复制」文字按钮。
一条记录备注长的时候，主操作根本不在第一屏。

`Scaffold(bottomBar = ...)` 里放一个 50dp 高的主按钮，
右侧在有条目网址时补一个「打开」。底部栏只在有密码时出现 ——
没密码的条目（纯笔记、证件号）不需要这个按钮。

同时加了 `Snackbar`：「密码已复制，30 秒后自动清空剪贴板」。

不只是为了好看：API 33 起系统不再让后台 toast 弹出，
而列表排序又用 `last_used_at`，复制后这一条会往上跳 ——
用户需要一个明确的"成了"的确认，否则会以为是自己点错了、列表才会动。

## 4. 桌面长按快捷方式

长按桌面图标直接出现两个入口：

| 快捷方式 | 落点 |
|---|---|
| 新建 | `vaultbook://new` → 新建页 |
| 生成密码 | `vaultbook://generator` → 生成器页 |

### 为什么用私有 scheme 而不是显式 `targetClass`

`shortcuts.xml` 里写不了 `${applicationId}` 占位符，而 debug 变体的
`applicationId` 是 `com.yg.vaultbook.debug`。硬编码 `com.yg.vaultbook`
会让 debug 包上的快捷方式点了没反应（或者去打开 release 版）。
用 `vaultbook://` 让系统按 intent-filter 解析，两个变体各自解析到自己身上。

### 清单里只声明 scheme

```xml
<data android:scheme="vaultbook" />
```

host 在 `MainActivity.handleIntent` 里判断。两个理由：

1. lint 的 `IntentFilterUniqueDataAttributes` 要求一个 `data` 标签只放一个属性 ——
   多个 host 会被组合成马赛克式的匹配矩阵，实际行为和写的人想的往往不一样；
2. 以后加快捷方式只要改 `handleIntent` 一行，不用再碰清单文件。

私有 scheme 没有对外暴露面，放开 host 不增加风险。

`Intent.ACTION_VIEW` 处理完要把 `action` 和 `data` **都**清掉：
只清 `action` 的话，从最近任务恢复时 `data` 还在，某些 ROM 会按 data 重新走一遍 VIEW 分发。

## 5. 顺手修掉的问题

| 问题 | 原因 | 修法 |
|---|---|---|
| `markUsed` 是死代码 | W1 写了没接 | 三处调用补上（见 §1） |
| 新建条目不在第一屏 | `createEntry` 不设 `lastUsedAt` | `lastUsedAt = now, useCount = 1` |
| 编辑后条目位置不动 | `updateEntry` 不更新 `lastUsedAt` | `copy(..., lastUsedAt = now)` |
| 复制后没有明确反馈 | 只靠 toast，API 33+ 弹不出来 | Snackbar |
| 清单 data 标签触发 lint 警告 | 一个 data 放两个属性 | 只放 scheme |

### 沙箱构建的一个坑（这次新出现）

`:app:compileDebugKotlin` 报：

```
Execution failed for task ':app:kspDebugKotlin'.
> java.nio.file.AccessDeniedException:
  C:\Users\34943\AppData\Local\Temp\kotlin-compiler-in-xxx.alive
```

KSP 在系统临时目录写标记文件被拒。解决：把临时目录指到工程内 ——

```powershell
$tmp = "$root\.toolchain\tmp"
$env:TEMP = $tmp; $env:TMP = $tmp
gradle ... -Djava.io.tmpdir="$tmp"
```

`TEMP`/`TMP` 环境变量与 `-Djava.io.tmpdir` 都要设，只设一个不够
（Gradle daemon 与被 fork 的 JVM 读的不是同一个）。
