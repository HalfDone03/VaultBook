# 1.15 无障碍抓取：标题不再记成浏览器名

## 现场

在夸克里搜「QQ邮箱」→ 打开登录页 → 输账号密码 → 点登录，本应用记下来的一条叫「夸克」。
用户看到的是一条以浏览器命名的记录，站点、账号、密码全挤在它下面。

## 三条病根

1. **标题取的是「最浅的文本节点」**。
   浏览器自己的工具栏、标签栏、标签页标题比网页内容浅得多，
   于是「最浅」必然落在浏览器自己的界面上 —— 记下来就是 App 名。
2. **浏览器里拿不到域名时，用浏览器包名当站点身份**。
   `com.quark.browser` 不是站点。把它当键的后果不是"名字难看"，而是
   **夸克里打开的所有网站共用一条记录**，下次在任意站点都可能被填进去。
3. **页面标题里的「登录」二字没被剪掉**。
   `QQ邮箱 - 登录`、`登录 | QQ邮箱` 这种 `<title>` 直接当记录名，
   列表里会看到一串「… - 登录」。

## 改动

- `A11yFormDetector.detect` 新增两个参数：`pageChrome`（宿主 App 自己的文案，永远不当标题）、
  `preferContentTitle`（是否按"先往网页正文里找"的规则）。
- 标题选择改成两级：浏览器里先在**深度 ≥ 4**（穿过浏览器 UI，落进 WebView 容器）的节点里找，
  找不到才退回全树；同时排除宿主 App 名与其「…浏览器」别名，以及
  `新建标签页`、`搜索或输入网址`、`无痕模式` 这类浏览器界面字眼。
- 新增 `tidyPageTitle`：按 `|`、` - `、`·` 分段，丢掉整段就是「登录 / 登陆 / 注册 / sign in」
  的段，取剩下的第一段 —— `QQ邮箱 - 登录` → `QQ邮箱`。只剪整段，不做模糊截断
  （站名本身带「登录」二字的情况仍保留）。
- `CaptureAccessibilityService`：`readForm(pkg)` 现在知道前台是谁，
  是白名单浏览器时传入宿主文案并开启正文优先；`capture()` 里
  **浏览器中 `packageNorm` 恒为 null**，认不出域名就只按标题认。
- 置信度里"站点身份"这一项，浏览器内允许由**页面标题**顶上 —— 否则
  认不出域名又没包名会被判成证据不足直接丢弃。

## 验证

- 新增 5 条识别层用例：夸克工具栏 + 网页正文取正文、只剩宿主文案时标题留空、
  工具栏占位字不算标题、`登录 | QQ邮箱` 剪成 `QQ邮箱`、非浏览器行为不变。
- 30 个测试类 506 例 0 失败。

## 仍然不认

- 浏览器把地址栏做成自绘、连 `contentDescription` 都不给的（拿不到域名，只能按标题认）。
- 网页本身没有可读标题（空白页、纯 canvas 渲染的登录框）—— 此时没有站点可认，
  记录名会退回域名或留空。
- 同一浏览器里两个不同站点取了同一个标题（如都叫「登录」）—— 会被剪成空标题，
  退回域名；没有域名就只能留空，不会拿浏览器名顶。
- 应用内 WebView 登录但宿主 App 不在白名单里（仍按包名匹配，不解析地址栏）。
