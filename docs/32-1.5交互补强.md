# 1.5 交互补强

这一版只做用户提的四件事，没有加新功能。

1. 分类可选更多
2. 编辑页能改全部字段
3. 回收站要有明确入口
4. 整体交互与功能做一次增删改查审查

## 一、分类从 16 个扩到 34 个

原来的内置分类是：登录、邮箱、社交、购物、支付、银行、银行卡、会员卡、游戏、证件、保险、车辆、Wi-Fi、服务器、笔记、其他。

这十六个覆盖的是"最常见的账号"，覆盖不了日常真正会存的东西：学校系统的账号、家里的路由器、外卖、快递、政务网站、各种订阅。

现在追加十八个：工作、学校、论坛、影音、音乐、网盘、外卖、出行、酒店、快递、医疗、政务、订阅、路由器、加密资产、教育、家庭、设备。合计 34 个。

三个实现上的取舍：

- **新分类一律追加在末尾，不插队。** 补种逻辑是增量的（只补库里没有的 id，排序号取当前最大值加一），老用户升级上来时，自己排过序的分类不会被打乱。
- **原十六个的 id 和顺序一个字没动。** 已经存过分类的记录，指向的还是原来那个 id，升级不会串分类。
- **分类的图标字段仍然不渲染。** 全项目没有分类图标映射表，加新的图标标识不会带来任何视觉变化，只是留了数据位。

分类数量上去以后，新建条目页原来那排平铺的分类标签会把表单挤到好几屏之外，所以改成了"当前分类 + 一个按钮"的样子，点开才是一个可搜索的分类列表（支持拼音首字母），列表底部可以直接新建。

## 二、编辑页：字段都在，只是看不见

用户的原话是"点击保存过的条目，点击编辑里只能更改标题名，并没有其他内容"。

查了代码，字段是齐的：标题、账号、密码、网址、动态码密钥、备注、分类、收藏、自定义字段，保存时也确实写回全部字段。问题在排版——十六个分类标签平铺成好几行，把备注和自定义字段顶到了两三屏以下，眼睛扫到第一个输入框就以为到头了。

这一版动的是可发现性，不是功能：

- 编辑态顶部加了一行说明，明说这九项都能改、往下滑就能看到。
- 表单加了两个分区标题（基本信息 / 备注、分类与补充），让人知道下面还有内容。
- 保存按钮从"滚动到最底部才看得见"挪到了底部常驻栏，编辑态左侧是删除，右侧是"保存修改"。
- 详情页正文底部加了一颗整宽的"编辑这条"，不再只靠顶栏那个没文字的小图标。

另外补了一个真实的丢数据风险：以前点返回键，整页直接弹掉，写了一半的密码就没了。现在进来时记一份字段指纹，改过才拦——弹出"不保存就退出？"，没改过就直接走。

## 三、回收站：入口藏得太深

回收站是有页面的，也能恢复、能单条清除、能全部清空。问题是入口只在列表页顶栏的"更多"下拉菜单里，用户根本没找到。

这一版把它提到设置页"整理"段的第一行，常驻显示，副标题直接写条数（"3 条，30 天后自动清除"）或者"空着。删掉的记录先放这里"。列表页那个下拉入口保留，两条路都能进。

删除条目后的提示也补了撤销：原来是"已移到回收站，30 天后自动清除"，只能看着；现在是同一个提示条带一个"撤销"，点一下当场恢复，不用再进回收站翻。

## 四、增删改查走查

按"每条数据从生到死能不能走通"过了一遍，改的都是断头路：

| 环节 | 原来 | 现在 |
| --- | --- | --- |
| 条目·增 | 手动填、粘贴识别、批量保存、分享进来 | 不变 |
| 条目·删 | 删除后只有一句提示 | 加"撤销"，当场恢复 |
| 条目·改 | 保存按钮在滚动尽头 | 底部常驻栏 + 详情页明文入口 + 未保存拦截 |
| 条目·查 | 搜索（含备注）、分类筛选、四种排序 | 不变 |
| 分类·增删改查 | 管理页可新建/重命名/删除/上下移 | 新建条目页也能就地新建 |
| 回收站 | 入口只在列表页下拉里 | 设置页常驻入口，带条数 |
| 自定义字段 | 增删 | 不变 |

空状态、错误提示、无结果提示原本就有，这轮核对过一遍，没有留空白的死页面。

## 五、验证

- 27 个测试类、441 个用例、0 失败（这一版没有改动纯逻辑，所以用例数不变；分类扩容与界面改动都是编译期能闭合的）。
- 编译、打包、混淆均通过；安装包版本号 150、版本名 1.5。
- 真机仍是空白：这一版改的全是"看得见摸得着"的东西（底栏会不会挡表单、分类弹层在小屏上会不会顶到键盘、撤销提示条停留够不够按），只能靠装上去看。

## 六、给下一位的提醒

- 分类补种是增量的，别再往 `BUILTIN_CATEGORIES` 中间插条目，插了会打乱老用户的排序。
- 编辑页的未保存拦截靠字段指纹比对，新增字段时记得同步加进 `signature()`，否则改那个字段不会被当成"改过"。
