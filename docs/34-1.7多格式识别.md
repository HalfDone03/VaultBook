# 1.7 多格式粘贴识别

本文件里的示例数据全部是编造的，形状与真实粘贴一致，值不是任何人的密码。

## 1. 起因

1.6 只能认「一行一条键值对 / 空行分段 / 横线分隔 / 连写」这几类，用户实际粘过来的东西比这杂得多。一次反馈里给了六种形状，全挂：

| 粘进来的东西 | 1.6 的结果 |
|---|---|
| `微信:demo_wx_001:Wx@123456` 三行 | 只出 1 条，账号成了 `demo_mail@example.com:Mail#2024`，密码成了下一行整段 |
| `平台,账号,密码,备注` 加两行 CSV | 出了 2 条，第二条账号 `Gm#654321`、密码 `邮箱测试`、网址 `demo.gmail` |
| `[{"platform":"微博",…},{"platform":"QQ",…}]` | 账号 `"account":"weibo_demo"`，标题 `[{"platform":"微博"` |
| `备注：备用密码在邮箱里` | 整行被当字段名吃掉，备注空着 |
| `https://demo_user:Demo%40123@example.com/login` | 账号 `Demo%40123@example.com/login` |
| `淘宝\tdemo_tb\tTb@123456` 制表符表格 | 密码 `淘宝\tdemo_tb\tTb@123456`，没有账号 |

另有一条第 2 项是界面问题：读出剪贴板后输入框里看不到内容，只显示"认出两组"。

## 2. 规则（按识别顺序）

`parse()` 现在按这个顺序试，命中就返回：

0. **JSON 对象** `{…}` — 键名走同一张字段名表，转义（`\"`、`\\`、`\uXXXX`）还原，数字型密码照样当密码。
0. **表格** — 首行当表头，分隔符是逗号 / 制表符 / 分号 / 竖线其一（取前四行都出现的那个），按列名装填；**必须同时有账号列和密码列**才认，否则放弃交给后面的规则。
0. **冒号链** `标签:账号:密码` — 一行至少三段、无空白、不含 `://`。标题取第一段（通用词「账号/用户名/account」不当标题，只在它后面还跟着值时才当值是账号）。
0. **键值对**（冒号 / 等号 / 空白分隔）— 新增 `备注` 类键进备注字段，`平台/应用/软件/application` 进标题。
0. **链接里的账号** — 逐行扫 `scheme://user:pass@host`，`%XX` 解码。
0. **链接当网址** — 取第一个不像邮箱的 host（跳过 `@` 前后的、跳过 `.apk`）。
0. **剩下的行按位置猜** — 剥序号、丢表头和横线行、平台名与账号粘连时拆开、两段且首段是纯中文平台名时当标题。

`parseMany()` 在此之上多三条整段规则：JSON 数组（≥2 条）、表格（≥2 行数据）、一行一条冒号链。

## 3. 刻意取舍

- **不用 `org.json`**：JVM 单测里它是 Android 桩，一调就 `not mocked`。手写的 `JSON_FIELD_REGEX` 只认扁平对象，嵌套结构不处理 —— 粘凭据几乎没有嵌套的。
- **表格必须带表头**：没有表头的两列文本，谁也不知道哪列是账号。宁可退回按行猜，也不猜错列。
- **两段全是汉字不算账号密码**：`项目,说明`、`淘宝,购物用` 这种是标签列或一句说明。真实的账号或密码至少带字母、数字或符号。这条是 486 例里唯一一次失败换来的 —— 早先它会产出「账号=项目、密码=说明」。
- **冒号链排在键值之前**：`邮箱:demo@x.com:Mail#2024` 里「邮箱」本身就是字段名，先走键值会把整串当账号。
- **键值正则加左侧词边界**：`demo_user:abc` 里的 `user` 会被当字段名，整条链接的账号就切没了。

## 4. 界面

- 粘贴框读剪贴板后强制重挂输入框（`key(resetKey)`），因为 Compose 的 `TextField` 在外部赋值时选区不同步，肉眼看就是"没灌进去"。手动打字不触发，光标不受影响。
- 输入框下面加一行「N 行 · M 字」，灌没灌进去不用猜。
- 单条候选卡片保留 1.6 的「账号密码反了？」对调。
- `applyParsed` 把识别出的备注写进备注框（原来是空的）；批量保存时每条带的备注一起存。

## 5. 用例

新增 `CredentialParserFormatsTest`（29 例），按七组铺开：

- 冒号链：三行各自成条、单条入口取第一条、通用字段名不当标题、密码里带冒号时整段保留
- 表格：CSV 带备注、制表符、分号、竖线、英文表头、没有账号列的表不当表格
- JSON：数组两条、单对象、转义还原、数字密码
- 备注：不再被当字段名丢掉、冒号写法里也留
- 链接：https 的 user/pass（含 `%40` 解码）、ftp、几条链接各成条、邮箱不会被当站点
- 老形状回归：两段平台名加账号、平台名和账号贴在一起、空白分隔字段名、行首序号、整行横线、纯网址不算凭据、纯标点不算凭据、备注单独存在也算有内容

总数 28 类 486 例，0 失败。

## 6. 还没做

- 嵌套 JSON、数组型字段不处理。
- 表格里单元格内含分隔符又没加引号的，会切歪。
- 真机验收仍然是空白：本机没有模拟器，识别逻辑靠单测覆盖，粘贴框的视觉与交互只能交给真机。
