# 17 · 外观重做说明（v1.4.0）

> 这一版没有改任何功能。只做了一件事：让它看起来像个 2024 年的应用。
> 动手前先诊断了"为什么丑"，因为随手调颜色只会把丑换成另一种丑。

---

## 1. 病根：层次是反的

旧版三个色值：

| 角色 | 旧值 | 问题 |
|---|---|---|
| `background` | `#FCFCFA` 近白 | 背景太亮 |
| `surface` | `#FFFFFF` 纯白 | 和背景几乎无差 |
| `surfaceVariant` | `#EDEDE8` 浅灰 | **卡片比背景更暗** |

结果：卡片陷进背景里，看着像老式表单的分组框。列表里十张同形状灰卡片一路排下去，眼睛找不到落点 —— 用户说的"丑"，主要是这个。

另外三个拖后腿的地方：

- 圆角全是硬编码的 `14.dp`，各页面还不一样；
- 字号层级没拉开（正文 16sp、小字 11sp，中间是空的）；
- 全静态 —— 点击没有反馈，列表一次性糊上来，切页面直接跳变。

---

## 2. 新的层次

```
background  #ECF1ED   暖灰    ← 最暗，垫在最下面
surfaceVariant #F5F8F5 近白   ← 次级卡片、输入框
surface     #FFFFFF   纯白    ← 条目卡片，配 1dp 阴影
```

白卡浮在暖灰背景上，层次一眼就分得清。主色从偏灰的 `#2E6B52` 换成 `#0B6E4F`（翡翠绿，饱和度够但不刺眼），补了琥珀色作次要色、雾蓝色作第三色 —— 需要区分"弱密码/分类/收藏"时有三种语义色可用，不必全挤在红色上。

深色模式同步重做：背景 `#0D1110`、卡片 `#171C1A`、次级 `#242B27`，卡片比背景亮一档，同样的层次逻辑。

字号层级补齐：

| 档位 | 值 | 用在哪 |
|---|---|---|
| `displaySmall` | 30sp Bold | 列表页大标题「账号本」 |
| `headlineSmall` | 24sp Bold | 详情页标题 |
| `titleLarge` | 21sp SemiBold | 页面标题 |
| `titleMedium` | 16sp SemiBold | 密码显示 |
| `bodyLarge` | 16sp Medium | 条目标题 |

圆角统一成一套：8 / 14 / 16 / 22 / 28。`extraSmall` 从 M3 默认的 4dp 提到 12dp —— 这个档位是输入框和 Chip 用的，4dp 会让整个表单看着像十年前的安卓。

## 3. 动效

新建 `ui/Motion.kt`，三个原语 + 一组统一时长（`Fast 150 / Base 240 / Slow 360`）。集中定义是为了避免每个页面各写一个 `200`、`300`，最后满屏都是不同节奏。

### 3.1 按压缩放

```kotlin
Modifier.pressScale(interactionSource, pressedScale = 0.97f)
```

`spring(dampingRatio = 0.55f, stiffness = 900f)` —— 带一点过冲，像按到实体按键。列表卡片 0.985（几乎察觉不到，但手指会觉得"有东西"），FAB 0.92，复制胶囊 0.93。

### 3.2 入场淡入上浮

```kotlin
Modifier.enterFadeSlide(delayMillis, distanceDp = 16f)
```

`graphicsLayer` 改 `alpha` 和 `translationY`，不触发重新布局。

### 3.3 列表错峰入场

每行延迟 `index * 40ms`，封顶 240ms（第 7 行之后同时出现，不然滑到第 20 行要等 800ms）。

**这里有个必须处理的坑**：`LazyColumn` 会回收并重建列表项，`remember` 会跟着重置。如果无脑给每行加入场动画，用户往回滚一次，那几行就重新播一次淡入 —— 像列表在抽筋。

解法是记住谁播过：

```kotlin
val playedIds = remember { mutableSetOf<String>() }
val isNew = remember(entry.id) { playedIds.add(entry.id) }
```

只有第一次出现才给延迟和 360ms；之后 `delay 0 / duration 1ms`（不能传 0，`tween(0)` 会立刻结束但状态机仍跑一轮）。

### 3.4 页面切换

`VaultApp` 里包了一层 `AnimatedContent`：新页从右侧淡入，旧页向左淡出。位移只给宽度的 **1/12**（约 90px）—— 是"有点方向感"，不是"整屏飞进来"。后者每次点进详情都像翻页 PPT，用久了累。

## 4. 视觉组件

新建 `ui/Components.kt`：

- **`EntryAvatar`** —— 渐变圆角方块 + 白色首字。8 组预设渐变（翡翠/雾蓝/琥珀/紫藤/玫瑰/青瓷/橄榄/品红），按站点标识的 hash 取色，所以同一个网站永远是同一个颜色，滑列表时能靠颜色定位。
  取色用 `(seed.hashCode() and 0x7FFFFFFF) % size` —— 不能写 `abs(hashCode())`，`Integer.MIN_VALUE` 取绝对值仍是负数，会数组越界崩掉。
- **`EmptyArtwork`** —— 空状态插画，纯 Canvas 画的：一本圆角"本子"、三条长度递减的记录线、右下角圆形徽章里一把锁。空列表最容易被做成一行灰字，那是整个应用最没有温度的角落。

### 4.1 列表页

- 弃用 `TopAppBar`，手写 `ListHeader`：左边 30sp 大标题 + 条目计数，右边三个图标。大标题是这一版观感变化最大的地方 —— 小标题居中那种正式感，对速查本是错的。
- 搜索框改成胶囊形（`CircleShape`）+ 白底 + 无指示线，有内容时右侧出现清空按钮。
- 条目卡片：白底 18dp 圆角 + 1dp 阴影，左边头像、右边「复制」胶囊。悬停按下有缩放。
- 强度点从 10dp 灰点改成 7dp 彩色点，且**无密码时不画**（灰色圆点会被读成"弱"）。

### 4.2 详情页

- 标题升到 `headlineSmall`，前面补一块 56dp 渐变头像 —— 和列表那一行对上，点进来不会觉得换了套 UI。
- 密码从 `bodyLarge` 灰字改成 `titleMedium` + `primaryContainer` 浅绿底 + 圆角 10dp + `letterSpacing 1.2sp`。密码是打开这条记录最想看的东西，值得最大的字；字距是为了让 `l/1`、`O/0` 一眼能分开。
- 三张卡片的容器色从浅灰换纯白，加 1dp 阴影、圆角 18dp。

### 4.3 其余页面

9 个文件、14 处卡片的 `surfaceVariant` 统一换成 `surface`（白卡浮在暖灰背景上）。这些页面结构不动，只换层次 —— 结构重做风险大于收益，而且它们本来也不是用户抱怨的地方。

## 6. 真机看什么

装上之后按这个顺序看，前三条是这一版的重点：

1. **列表页第一眼** —— 白卡片有没有浮起来、头像颜色是否丰富、点进去再返回时有没有重新播入场动画。
2. **点一条记录** —— 右侧滑入是否轻、详情页密码底色是否顺眼。
3. **按住卡片 / 按住 FAB** —— 有没有轻微缩小。
4. **长按屏幕截图对比深色模式** —— 深色下卡片是否比背景亮一档。
5. **空状态** —— 删掉全部条目（或新建一个空库）看那幅插画。

## 7. 已知限制

1. **没在任何真机上看过**。这仍然是纯静态推演 + 编译通过 —— 上面所有判断来自代码，不是来自眼睛。颜色在真实屏幕上偏冷偏暖、动画在低端机上是否掉帧，都还没验证。
2. 徽标（launcher icon）还是旧的实心锁，没跟着新配色重画。
3. 只有 Compose 内置动画，没做共享元素转场（列表卡片 → 详情页头像的连续动画）。那个收益明显但要 API 21+ 的 `SharedTransitionLayout`（Compose 1.7 起稳定），会牵连页面结构，留到下一版。
4. 深色模式没有单独调过渐变头像的色板，深色下 8 组颜色偏亮，但没有出戏。
5. 动画没有"减弱动态效果"的无障碍开关（系统设置了 `animator_duration_scale = 0` 时会自动跳过，但没有应用内开关）。
