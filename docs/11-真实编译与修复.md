## 2. 四个环境坑（都不是代码问题，但每个都能卡住一整天）

### 2.1 `curl` / `Invoke-WebRequest` 必然失败

```
curl: (35) schannel: AcquireCredentialsHandle failed: SEC_E_NO_CREDENTIALS
```

不是网络不通，是 **schannel 在当前受限令牌下拿不到证书句柄**。改用 **Node 的 `https` 模块**（走 OpenSSL，完全正常）下载。工程内留了 `.toolchain\fetch.mjs`。

### 2.2 `sdkmanager` 报 "Failed to download any source lists"

真正原因是 **Java 优先走 IPv6 而 IPv6 不可用**。加一个系统属性立刻解决：

```powershell
& "sdkmanager.bat" -Djava.net.preferIPv4Stack=true --list
```

同一个属性也能写进 `gradle.properties` 的 `org.gradle.jvmargs`。

### 2.3 中文路径让 AGP 直接拒绝构建

工程路径含「账号本」，AGP 报 `Your project path contains non-ASCII characters`。两步解决：

1. `gradle.properties` 加 `android.overridePathCheck=true`
2. `local.properties` 里的路径**必须写成 `\uXXXX` 转义** —— Gradle 按 ISO-8859-1 读 `.properties`，直接写中文会乱码导致 `sdk.dir` 失效：

```properties
sdk.dir=C:/Users/34943/Documents/Project/\u8D26\u53F7\u672C/.toolchain/android-sdk
```

### 2.4 Gradle 的 file watcher 起不来

`Couldn't open current thread, error = 5`（权限）。构建命令加 `--no-watch-fs`，`gradle.properties` 里 `org.gradle.vfs.watch=false`。

## 3. 首次编译：30+ 条真实错误

按性质分五类。**教训：Android 框架的类名/方法名不能凭记忆写，必须 `javap` 查。**

### 3.1 回调类的真实名字（最容易错的一类）

`javap` 查 `android.jar` 得到的真相：

| 我原来写的 | 真相 |
|---|---|
| `FillRequest.FillCallback` | **`android.service.autofill.FillCallback`**（独立顶层类，不是嵌套类） |
| `SaveRequest.SaveCallback` | **`android.service.autofill.SaveCallback`**（同上） |
| `callback.finish(response)` | **`FillCallback` 没有 `finish()`** —— 只有 `onSuccess(FillResponse)` / `onFailure(CharSequence)` |
| `callback.finish(null)` | 给不出响应时走 **`onFailure(null)`**（`onSuccess` 的参数是非空的） |

嵌套写法会让 `override` 全盘失败，然后连带报出一串 "Unresolved reference 'finish'" —— 看起来像响应构造的问题，实际只是类型名写错。

### 3.2 `AssistStructure` 的 API 名

| 我原来写的 | 真相 |
|---|---|
| `structure.windowCount` | `structure.windowNodeCount`（`getWindowNodeCount()`） |
| `structure.getWindowAt(i)` | `structure.getWindowNodeAt(i)` |
| `window.rootView` | `window.rootViewNode`（`getRootViewNode()`） |
| `node.idTitle` | **不存在**（那是 `AccessibilityNodeInfo` 的）→ 改用 `window.title`（`WindowNode.getTitle()` 真有） |
| `node.isEditable` | **不存在** → 判据只用 `autofillType == View.AUTOFILL_TYPE_TEXT` |

顺带一个收获：`WindowNode.getTitle()` 能拿到**真正的窗口标题**（"登录 - 淘宝网"），比原来退而求其次用的 Activity 类名（"LoginActivity"）准得多，现在优先用它。

### 3.3 `SaveInfo.Builder` 的两套 ID 不能混用

```kotlin
SaveInfo.Builder(type, requiredIds)   // 构造函数已经设了 required ids
      .setRequiredIds(ids)            // ← 这个重载要的是 int[]（View.getId()）
```

两套标识（`AutofillId` 与 `int` View id）混用必然编译失败。构造函数已经设过，删掉 `setRequiredIds` 那行即可。

### 3.4 `CharArray` 没有 `isNullOrEmpty()`

`isNullOrEmpty()` 是 `CharSequence?` 的扩展。`CharArray?` 要写：

```kotlin
if (password == null || password.isEmpty()) { ... }
```

额外好处：条件收窄后，后面三处调用拿到的就是非空 `CharArray`，不用再 `!!`。

### 3.5 Kotlin 空安全与 `runCatching` 的类型推断

- `map["iter"].toIntOrNull()` → `map["iter"]?.toIntOrNull()`（Map 取值是 `String?`）
- `runCatching { ... repository?.audit(...) }` 块尾是 `Unit?` → 推断成 `Result<Unit?>`
  → 与签名 `Result<Unit>` 不符。块尾补一行显式 `Unit`。
- `for (key in hostCandidates(host))` 里 `host` 是 `String?` → 外面包 `if (host != null)`。

## 4. ⚠ 最严重的一个：`Utf8.encode` 缺 3 字节分支

**这是本文档里唯一一个会造成数据损坏的 bug，而且是从 W0 就存在的。**

`Utf8.encode` 的 `when` 分支原来是：

```
1. c < 0x80          → 1 字节
2. c < 0x800         → 2 字节
3. 代理对            → 4 字节
4. else              → 写 U+FFFD   ← 中文全落在这里
```

**缺了 `U+0800..U+FFFF` 的 3 字节分支。** 后果：

> 任何中文（以及日文、全角标点、变体选择符 U+FE0F）在**加密之前**就被替换成了 U+FFFD。用户存一条中文备注、一个中文密码、一个中文自定义字段，读回来全是 `???`。

损坏发生在 encode 阶段，所以密文、解密、AAD 校验**全都正常工作** —— 数据「成功地」存进去、「成功地」读出来，只是内容是错的。静态审查很难发现，因为代码看起来分支齐全。

被抓出来的方式：

```
expected:<账号本·我的密码管理器> but was:<���·�������>
```

`·`（U+00B7，2 字节）好的，中文（3 字节）全废，emoji（4 字节）也好的 —— 这个分布直接指向「只有 3 字节路径有问题」。

修复后补的三条断言（已进 `Utf8Test`）：

- 中文往返
- emoji + 变体选择符往返（`🛡️` = U+1F6E1 + U+FE0F）
- 混合文本往返（`Pa55·中文·🔐·ñ·Ω`）

**这一条值得记住：加密代码的正确性不能靠"看起来对"，必须靠往返测试覆盖到每一个字节长度。** 1/2/3/4 字节各一条，缺任何一条都可能漏掉整类字符。

## 5. 单测怎么跑

Gradle 的 `testDebugUnitTest` 在本沙箱下起不来 —— 测试 worker 进程报：

```
ClassNotFoundException: worker.org.gradle.process.internal.worker.GradleWorkerMain
IOException: 管道正在被关闭
```

这是沙箱对子进程管道的限制，不是工程问题。绕过方式：**直接用 JUnitCore 跑编译好的 class**。

```powershell
$testDir = (Resolve-Path "app\build\tmp\kotlin-classes\debugUnitTest").Path
$mainDir = (Resolve-Path "app\build\tmp\kotlin-classes\debug").Path
$c = ".toolchain\gradle-home\caches\modules-2\files-2.1"
$cp = @(
  $testDir, $mainDir,
  "$c\junit\junit\4.13.2\8ac9e16d933b6fb43bc7f576336b8f4d7eb5ba12\junit-4.13.2.jar",
  "$c\org.hamcrest\hamcrest-core\1.3\42a25dc3219429f0e5d060061f71acb49bf010a0\hamcrest-core-1.3.jar",
  "$c\org.jetbrains.kotlin\kotlin-stdlib\2.0.21\618b539767b4899b4660a83006e052b63f1db551\kotlin-stdlib-2.0.21.jar",
  "$c\org.jetbrains.kotlinx\kotlinx-coroutines-core-jvm\1.9.0\9beade4c1c1569e4f36cbd2c37e02e3e41502601\kotlinx-coroutines-core-jvm-1.9.0.jar"
) -join ';'

# 先编译测试源
& ".toolchain\gradle\bin\gradle.bat" :app:compileDebugUnitTestKotlin --no-daemon --no-watch-fs

$classes = Get-ChildItem -Recurse -Filter *.class $testDir |
  ForEach-Object { $_.FullName.Substring($testDir.Length + 1) -replace '\\','.' -replace '\.class$','' } |
  Where-Object { $_ -notmatch '\$' }

& ".toolchain\jdk\bin\java.exe" "-Dfile.encoding=UTF-8" -cp $cp org.junit.runner.JUnitCore @classes
```

结果：

```
Time: 0.244
OK (253 tests)
```

**注意 `-Dfile.encoding=UTF-8` 必须加**，否则中文断言失败时控制台输出全是 `?`，看不出差在哪。

在你自己机器上（有完整 Android Studio）直接用 `./gradlew :app:testDebugUnitTest` 即可，不需要这套绕法。

## 6. 修复的一处测试自身错误

`EntryDraftTest` 的「searchText 跳过为空的字段」写成：

```kotlin
val text = summary(...)          // 拿到的是 EntrySummary 对象
assertEquals("只有标题", text)   // 断言一个对象等于一个字符串，永远不成立
```

应为 `summary(...).searchText()`。Kotlin 的 `assertEquals(Object, Object)` 重载让这个错误顺利通过编译 —— 测试代码也会有 bug，跑起来才知道。
