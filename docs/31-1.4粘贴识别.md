# 1.4 粘贴框与连写识别

## 1. 这一轮从哪来

用户连着提了几次同一段话，说明前几版没解决：

> 新建条目里，顶部的「点击这里粘贴」应该设为一个文字框，而不应该是点击后就自动获取了。
> 粘贴里的自动识别账号密码还是有 bug，多个一起粘贴进去的时候，标题识别不到，账号被识别成一整行，后面的内容就没后续了，识别的太烂了。

两条都是真问题，而且第一条是设计与用户预期不符，第二条是解析器漏了一整类形状。

**本文件里的示例数据全部是编造的**，形状与用户当时给的样本一致，值不是任何人的真实密码。界面里的示例文案同理。

## 2. 第一条：粘贴入口改成真的输入框

旧做法是页面顶部一个灰盒子，写着「点击这里粘贴」，点下去偷偷读剪贴板、识别、填表。问题有三层：

- 用户想贴的东西可能不在剪贴板里，可能是别处的一小段笔记，得先复制再回来；
- 点一下就把表单改了，看不见发生了什么，改错了还得自己回忆原来填了什么；
- 进场时还会自动读一次剪贴板，等于用户没点也在读。

现在换成一个真正的多行文本框（等宽字体，三到七行高），下面直接显示识别结果：

- 输入框下方左侧是「读剪贴板」（想要快捷方式的人有），右侧是「清空」；
- 框里没字时不显示任何结果；
- 认出一条时显示「认出这一条」，带标题、账号、密码原文和一个「填入表单」；
- 认出多条时显示「认出 N 组账号密码」和「看看」，进去是原来那张批量预览表；
- 认不出时给一句灰字提示，不弹窗、不报错。

三个刻意的取舍：

1. **不做边打边自动填**。手打时每敲一个数字，识别器都会认为有结果，表单会在眼皮底下被反复改写。识别结果只展示，动作由「填入表单」触发。
2. **不用 `rememberSaveable` 存这段文字**。里面是明文密码，放进 Bundle 就等于让它进了系统进程的序列化数据。转屏会丢，可以接受。
3. **识别结果里的密码照原文显示**。以前是打点遮盖，但原文就在上面输入框里，遮盖没有意义，反而让人没法核对认对了没有。

## 3. 第二条：连写识别

### 3.1 为什么原来认错

这类样本的共同点是：**既没有空格，也没有冒号**。

```
云盘账户密码Zx8Kq2Lm7V
云盘Zx8kq2lm7v.
邮箱平台密码Zx8kq2lm7v.
```

旧解析器对多行文本按这个顺序试四条规则：一行多列（按空白或逗号分列）、空行分段、重复的 key 切块、以上都不成立时退回猜。前三条都要求有分隔符，所以落到「退回猜」：

- 猜的时候先看首行像不像站点名。判断条件是「够短、不含数字」。首行既长又含数字，判定为不像；
- 于是认为整段是一条记录：标题空着，账号取第一行整行，密码取第二行，第三行丢弃。

结果和用户描述的完全一致：标题没有，账号是第一行整行，后面两条消失。

### 3.2 加一条规则：整段每行都是「名字 + 值」的连写

判断一行是不是连写，看这几件事：

- 不含任何空白、不含冒号等号之类的分隔符（含就交给原有规则，不动）；
- 里面存在「中文/汉字 → 英文数字」的字符交界，取**最后一处**当切点。取最后一处是为了让「云盘账户密码」这种自带「账户」二字的平台名整块留在左边；
- 右半边不能是中文，且必须含数字或 @（密码和账号都长这样，纯英文单词不算）；
- 右半边同时有字母和数字 → 认为是密码；纯数字 → 可能是密码也可能是手机号，由左边结尾的标签决定。

左边结尾决定名字怎么裁：

| 左半边结尾 | 判定 | 存进去的标题 |
| --- | --- | --- |
| 密码 / 口令 / password / passwd / pwd | 右半边是密码 | 去掉这个后缀 |
| 账号 / 帐号 / 账户 / 用户名 / 手机号码 / 手机号 / username / account | 右半边是账号 | 去掉这个后缀 |
| 以上都不是 | 看右半边形态 | 左半边原样 |

所以「云盘账户密码Zx8Kq2Lm7V」得到标题「云盘账户」、密码照抄；「邮箱平台密码Zx8kq2lm7v.」得到「邮箱平台」、密码带那个句点；「支付宝账号13800138000」得到「支付宝」加账号；「云盘账户Zx8kq2lm7v」里「账户」不算标签结尾，标题仍是「云盘账户」。

这条规则挂在两处：

- 整段粘贴时，如果**每一行**都能这么拆、且拆出两条以上，就按行拆成多条；
- 单条粘贴时，如果只剩一行没被别的规则吃掉，先试连写，试不出来才走原来的猜。

含空格的行、含冒号的行、`标题：淘宝` 这种三行一条、`淘宝 138 pwd` 这种表格形状，都不满足「不含空白」或「不含冒号」，一律走原路径，不受影响。

## 4. 测试

新增 7 个用例，全部用编造的示例值，形状与真实样本一致：

- 三行连写拆成三条（断言标题是云盘账户 / 云盘 / 邮箱平台，三个密码各自对上，账号都为空）；
- 单行连写拆出标题和密码；
- 「支付宝账号13800138000」按账号处理，标题是支付宝；
- 「淘宝13800138000」纯数字尾巴当账号；
- 「云盘账户Zx8kq2lm7v」平台名自带的「账户」二字保留在标题里；
- 带空格的列仍按列拆（不被连写规则抢走）；
- 带冒号的行仍走 key value（同上）。

## 5. 结果

版本 1.4，测试 27 个类 441 个用例全过（原 434，新增 7）。安装包与 1.3 体积一致（同样的资源与代码份额，差异只在字符串与逻辑分支），哈希不同。

已知没验证的：仍然没有真机。文本框的高度、等宽字体在不同 ROM 上的观感、粘贴面板的键盘遮挡，都只能装到手机上才能确认。
