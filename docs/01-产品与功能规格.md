# 01 · 产品与功能规格

## 1. 产品定位

**一句话**：把"我注册过哪些网站、账号是什么、密码是多少"这件事，从脑子和微信收藏里搬到一个加密的本地保险库，并且在登录时自动帮你填、自动帮你存。

- **形态**：纯本地 Android 应用（APK）。不要求联网，无账号体系，无云端同步（v1）。
- **核心用户**：自己用。手机上装了 30～200 个 App / 网站，密码靠记忆和重置找回的人。
- **对立面（不做的事）**：
  - 不做社交 / 分享 / 团队协作。
  - 不做浏览器扩展（v1）。
  - 不做明文导出（导出必须二次验证 + 加密或明确警告）。
  - 不做"自动登录"（不代替用户点击登录按钮，只填不提交）。

## 2. 核心用户场景

### S1 · 首次注册后自动存档（主场景）
用户在 Chrome 上注册了某网站，输入了手机号/邮箱 + 密码，点了注册/登录。切回桌面时，通知栏弹出一条：**「已捕获 example.com 的登录信息 —— 保存 / 修改 / 忽略」**。点保存 → 自动归档，标题取域名，分类猜为"网站"。

### S2 · 登录时自动填充
用户在某个 App 的登录页，点账号输入框 → 键盘上方出现「账号本」的候选项（Autofill 官方 UI），选中后用户名密码一起填上。

### S3 · 手动补录 / 修改
用户想起一个老账号，进 App → 点「+」→ 填标题/账号/密码/网址/备注 → 保存。或者打开已有条目改密码，系统自动留一条历史版本。

### S4 · 找密码
在列表页搜"淘宝"或"taobao" → 命中 → 点进去 → 点密码右侧「复制」→ 30 秒后剪贴板自动清空。

### S5 · 体检
安全中心显示：「你有 7 个弱密码、3 组重复密码、12 个超过 1 年没改」。点进去逐条修。

### S6 · 换手机
设置 → 导出加密备份 → 生成 `.vbk` 文件 → 新机导入 → 输入备份密码 → 全部恢复。

## 4. 逐功能验收标准

### 4.1 条目 CRUD

- **AC-1** 新建条目时「标题」为空 → 若填了网址，标题自动取域名主体（`www.taobao.com` → `淘宝` 若无内置映射则取 `taobao.com`）；否则取用户名；再否则阻止保存并提示。
- **AC-2** 标题 + 用户名 + 密码 + 网址 + 备注 五个字段在数据库中以**密文**存储（`BLOB`），SQLCipher 再包一层。
- **AC-3** 编辑页离开时若有未保存修改，弹「放弃修改？」确认。
- **AC-4** 删除进回收站（软删除 `deleted_at`），保留 30 天，可恢复；超过 30 天由 `WorkManager` 定期物理清除。
- **AC-5** 修改密码字段时，旧值写入 `entry_history`，同一条目最多保留 20 条，超出按时间淘汰。

### 4.2 自动捕获（核心）

- **AC-6** 捕获判定必须同时满足：
  1. 页面上存在**至少一个密码型输入框**（`inputType` 含 `TYPE_TEXT_VARIATION_PASSWORD` / `TYPE_NUMBER_VARIATION_PASSWORD`，或 Accessibility `isPassword=true`，或 HTML `type=password`）；
  2. 密码框非空，长度 ≥ 1；
  3. 存在至少一个疑似用户名框（`autofillHints` 命中 username/email/phone，或 hint 文案命中 `账号|邮箱|手机|用户名|account|email|login|user`），且非空；若无用户名框但存在"记住手机号"等，允许只存密码。
- **AC-7** 捕获后**不直接落库**，先进 `CaptureBuffer`（内存，TTL 90 秒，最多 20 条），再由 `CaptureArbiter` 打分：
  - 置信度 = 0.35×有密码框 + 0.25×有用户名框 + 0.2×域名/包名可识别 + 0.1×检测到提交动作 + 0.1×页面标题不空
  - ≥ 0.85 → 直接弹确认条；0.6–0.85 → 仅在用户主动打开 App 时出现在「待确认」列表；< 0.6 → 丢弃
- **AC-8** 去重：同一 `host_or_package + username` 在 5 分钟内重复捕获 → 只保留最新值，不重复提示。
- **AC-9** 已存在同 `host_or_package + username` 条目且密码不同 → 确认条文案变为「**密码有变化，更新？**」，点更新则写历史 + 更新主记录。
- **AC-10** 确认条 10 秒无操作自动收起（数据仍留在「待确认」列表，可在 App 内补确认）。
- **AC-11** 用户点「忽略」→ 该 `host` 加入 24 小时静默名单，期间不再提示（可在设置里清空）。
- **AC-12** 捕获到的密码**永不写入日志、永不上报**；`CaptureBuffer` 在内存中保存 `CharArray`，超时或消费后立即 `Arrays.fill('\u0000')`。
- **AC-13** 无障碍通道可整体关闭；关闭后仅保留 Autofill 通道，功能降级但不报错。

### 4.3 自动填充

- **AC-14** 用户启用本应用为 Autofill 服务后，在任意登录页聚焦输入框，候选项需在 **300ms 内**返回（异步查询用 `ViewNode` 的 `webDomain` 直接匹配索引）。
- **AC-15** 数据集展示格式：主标题 = 条目标题，副标题 = 用户名，右侧 = App 图标。
- **AC-16** 同一域名下多个账号 → 返回多个 Dataset（最多 5 个）+ 一个「搜索账号本」入口（启动 Auth Activity 后回填）。
- **AC-17** 匹配优先级：`webDomain` 精确匹配 > `packageName` 精确匹配 > 域名后缀模糊（`*.example.com`）> 用户手动选择过的 `site_mapping` 记录。
- **AC-18** 填充后不自动提交表单（绝不调用 click）。
- **AC-19** 若数据集包含 TOTP，填充后 3 秒内 Toast 提示当前验证码（可关）。

### 4.4 解锁与锁定

- **AC-20** 冷启动必须解锁；解锁页无任何密码明文预览（列表标题也不预加载，解锁后才加载）。
- **AC-21** 生物识别失败 3 次 → 回落到主密码。主密码连续错误 5 次 → 延迟 30 秒；10 次 → 5 分钟；15 次可选「清空本机数据」。
- **AC-22** 自动锁定按设置执行；`onStop` 记录时间戳，超时后清空内存中的 DEK 与已解密缓存。
- **AC-23** 解锁状态下全程 `FLAG_SECURE`，最近任务缩略图为空白。

### 4.5 安全中心

- **AC-24** 弱密码判定：长度 < 8 直接弱；命中内置 Top-1000 弱密码表直接弱；否则用字符集熵估算，`熵 < 40 bit` 记弱。
- **AC-25** 重复密码：对密码明文做 SHA-256 后分组，同组 ≥ 2 条列出（仅内存计算，结果不落库）。
- **AC-26** 每一项都能点击跳转到对应条目的编辑页，修完实时从不合格列表移除。

### 4.6 导入导出

- **AC-27** 导出 `.vbk`：用户设定备份密码（可与主密码不同）→ Argon2id 派生 → AES-256-GCM 加密 zip → 文件头写入 `VBK1` + 版本 + KDF 参数。导入时校验头，参数不匹配则提示版本不兼容。
- **AC-28** CSV 导入需先展示「预检报告」：共 N 行、可识别 M 行、缺密码字段 K 行、疑似重复 D 行，用户确认后才写入。
- **AC-29** 明文导出必须在输入主密码 + 勾选「我明白明文文件有风险」后才执行，且导出后立即提示删除时机。
- **AC-30** 导入过程整体在一个事务中，中途失败全部回滚。

## 6. 非功能需求

- **启动速度**：冷启动到解锁页 < 800ms（中端机）。
- **解锁耗时**：主密码解锁 < 600ms（Argon2id 参数 t=3, m=64MB, p=2 约 300–500ms，属预期耗时，需显示进度）。
- **包体积**：< 15 MB（不含 debug 符号）。
- **离线**：除可选的泄露检测外，全部功能离线可用。
- **无障碍**：TalkBack 全流程可操作；对比度 ≥ 4.5:1。
- **兼容性**：Android 8.0 – 15；覆盖 MIUI / HyperOS、ColorOS、OriginOS、HarmonyOS(兼容层)、OneUI 的后台保活差异。
- **崩溃率**：< 0.5%（自建本地崩溃日志，不上传）。
