# 02 · 技术架构与数据模型

## 1. 技术选型

| 层 | 选择 | 理由 |
|---|---|---|
| 语言 | Kotlin 2.0 | 官方主推；协程 + Flow 天然适配"解密后再渲染"的异步链 |
| UI | Jetpack Compose (Material 3) | 声明式，页面状态机清晰；无需 XML 布局 |
| 导航 | Navigation-Compose，类型安全路由 | |
| DI | Hilt | |
| 本地库 | Room + **SQLCipher for Android** | 全库页级加密；Room 负责 DAO 与迁移 |
| 字段加密 | AES-256-GCM（Tink 或手写 `Cipher`） | 每字段独立 IV，防同值碰撞 |
| 密钥派生 | PBKDF2-HMAC-SHA256（默认，JDK 内置）/ 可选 Argon2id（`com.lambdapioneer.argon2kt`） | 内置实现零依赖，Argon2 需额外 .so |
| 生物识别 | androidx.biometric + Android Keystore（`setUserAuthenticationRequired`） | 密钥绑定生物特征，解封即通过 |
| 偏好设置 | DataStore(Preferences) | 存非敏感配置 |
| 后台任务 | WorkManager | 回收站清理、备份提醒 |
| 图形 | Coil（图标）、Vico 或自绘 Canvas（TOTP 环） | |

**关键取舍**：不做云端、不做账号体系、不做多设备同步 —— 攻击面最小化。

## 3. 加密体系

### 3.1 密钥层级

```
                  用户主密码 (String, 仅内存 CharArray)
                          │
                   KDF(salt, params)          ← Argon2id 或 PBKDF2
                          ▼
                    KEK_master (32B)
                          │  AES-256-GCM 解封
                          ▼
      ┌──────────────►  DEK (32B, 随机生成，永不变)  ◄──────────────┐
      │                    │                                        │
      │                    ├── AES-256-GCM 逐字段加解密              │
      │                    │                                        │
      │                    └── 解封 dbKey (32B) → SQLCipher 口令      │
      │                                                             │
   Keystore deviceKey (AES-GCM, setUserAuthenticationRequired) ──────┘
      │  （生物识别解锁路径：BiometricPrompt + CryptoObject 解封）
      ▼
   wrapped_dek_device
```

**为什么这样设计**：
- 改主密码只重算 `KEK_master` 并重新包裹 DEK，**不需要重加密整个数据库**。
- 生物识别解锁不解主密码，直接用 Keystore 密钥解封 DEK；主密码仍是最终后路。
- SQLCipher 口令独立，与 DEK 分离，改主密码不影响库文件。

### 3.2 KDF 参数

| 算法 | 参数 | 耗时目标 | 备注 |
|---|---|---|---|
| PBKDF2-HMAC-SHA256（默认） | iterations = 210_000，salt 32B 随机 | 300–500ms | 零依赖，兼容老机 |
| Argon2id（可选） | t=3, m=64MiB, p=2 | 400–700ms | 需 argon2kt；低内存机降 m=32MiB |

`vault_meta.kdf_params` 存 JSON：`{"algo":"argon2id","t":3,"m":65536,"p":2}`，升级参数时按记录值解密旧数据，下次保存时迁移。

**必须显式指定 `PBEKeySpec(char[], byte[], iter, 256)` 与 `"PBKDF2WithHmacSHA256"`**，不要用 `SecretKeyFactory.getInstance("PBKDF2WithHmacSHA1")`（默认 128bit 且迭代过低）。

### 3.3 字段密文包格式

```
CryptoBlob (binary):
  offset 0  : 1B   version (0x01)
  offset 1  : 1B   flags   (bit0: 绑定 AAD 的字段名)
  offset 2  : 12B  iv      (GCM nonce，每条记录每字段随机)
  offset 14 : NB   ciphertext
  offset 14+NB : 16B tag
AAD = "$entryId|$fieldName"   // 防止密文被搬运到别的字段/条目
```

- 明文 UTF-8 编码后加密；空值存 `null` 而非空密文，省空间。
- 解密失败 → 抛出 `CryptoException`，UI 显示「该字段无法解密（可能是备份不完整）」，不崩溃。

### 3.4 内存卫生

- 密码字段用 `CharArray` 处理，用完 `Arrays.fill(arr, '\u0000')`。
- 解锁后 DEK 缓存在 `VaultSession`（`@Singleton`），锁定即 `key.fill(0)` 并置 null。
- 已解密条目缓存用 `LruCache<String, PlainEntry>`，容量 30，锁定清空。
- 禁用 `Debuggable` 生产包；`android:allowBackup="false"`；`FLAG_SECURE`。

### 5.2 onFillRequest 处理流程

```kotlin
override fun onFillRequest(
    request: FillRequest,
    cancellationSignal: CancellationSignal,
    callback: FillCallback
) {
    val ctx = request.fillContexts.lastOrNull() ?: return callback.finish(null)
    val snapshot = AssistStructureParser.parse(ctx.structure, request.callingPackageName)
    // snapshot: host(webDomain，最可靠), packageName, userField?, pwdField?, submitButton?, htmlTag

    // 1) 无论如何先构造 SaveInfo，这样即便我们不填充也能收到 onSaveRequest
    val saveInfo = FillResponseFactory.buildSaveInfo(snapshot)

    if (!vaultSession.isUnlocked) {
        // 未解锁：仍然返回 SaveInfo，捕获照旧生效（用户手动输入会被记下）
        val resp = FillResponse.Builder().setSaveInfo(saveInfo).build()
        return callback.finish(resp)
    }

    // 2) 匹配候选
    val candidates = autofillMatchRepo.match(snapshot, limit = 5)   // 索引查询，<30ms

    val builder = FillResponse.Builder().setSaveInfo(saveInfo)
    candidates.forEachIndexed { i, entry ->
        builder.addDataset(FillResponseFactory.buildDataset(snapshot, entry, i))
    }
    // 3) 兜底入口：搜索账号本
    builder.addDataset(FillResponseFactory.buildSearchEntry(snapshot))
    // 4) API 30+ 追加键盘内联建议
    if (Build.VERSION.SDK_INT >= 30) {
        FillResponseFactory.inlinePresentations(snapshot, candidates)?.let { list ->
            builder.setInlinePresentation(list)   // 或按需 addDataset 内联
        }
    }
    callback.finish(builder.build())
}
```

### 5.3 AssistStructureParser 规则

遍历 `structure.getWindowNodeAt(i).root` → 递归 `ViewNode`。对每个节点收集：

| 取值 | 来源 | 用途 |
|---|---|---|
| `autofillId` | `node.autofillId` | 构造 `Dataset.setValue` 的 key，**必须** |
| `autofillHints` | `node.autofillHints` | 命中 `AUTOFILL_HINT_USERNAME/EMAIL_ADDRESS/PHONE/PASSWORD/NEW_PASSWORD` → 强判定 |
| `inputType` | `node.inputType` | `TYPE_TEXT_VARIATION_PASSWORD`(0x80)、`TYPE_TEXT_VARIATION_WEB_PASSWORD`(0xe0)、`TYPE_NUMBER_VARIATION_PASSWORD`(0x10) → 密码框 |
| `htmlInfo.tag` | `node.htmlInfo?.attributes` 里的 `type` | WebView 里 `type=password` 判定 |
| `node.text` | `node.text` | 提交后取实际输入值（onSaveRequest 阶段） |
| `webDomain` | `node.webDomain` | **浏览器真实域名，优先作为 host** |
| `idEntry` | `node.idEntry` | 例如 `loginForm:username`，辅助判定 |
| `isFocused` | `node.isFocused` | 判断用户正在操作哪个表单 |

输出 `FormSnapshot`：

```kotlin
data class FormField(val autofillId: AutofillId, val kind: FieldKind, val text: String?)
enum class FieldKind { USERNAME, PASSWORD, EMAIL, PHONE, OTP, SUBMIT, UNKNOWN }

data class FormSnapshot(
    val packageName: String,
    val host: String?,              // webDomain 归一化后的 eTLD+1
    val fields: List<FormField>,
    val submitId: AutofillId?,
    val pageTitle: String?,
    val hasPwdField: Boolean,
    val hasUserField: Boolean
)
```

**host 判定优先级**：`webDomain`（存在即用） > 浏览器场景下用 `packageName` 做粗键（`com.android.chrome`）但把 webDomain 记进 `host_norm` > 原生 App 用 `packageName` 作为 `package_norm` 主键。

### 5.4 保存事件（自动抓取的关键）

```kotlin
override fun onSaveRequest(request: SaveRequest, callback: SaveCallback) {
    val ctx = request.fillContexts.lastOrNull() ?: return callback.finish()
    val snapshot = AssistStructureParser.parse(ctx.structure, request.callingPackageName)
    val username = snapshot.fields.firstOrNull { it.kind in setOf(USERNAME, EMAIL, PHONE) }?.text
    val password = snapshot.fields.firstOrNull { it.kind == PASSWORD }?.text ?: run {
        callback.finish(); return                       // 没有密码不处理
    }
    CaptureBuffer.put(CaptureCandidate(
        host = snapshot.host, pkg = snapshot.packageName,
        username = username, password = password,
        confidence = CaptureArbiter.score(snapshot),
        source = Source.AUTOFILL
    ))
    callback.finish()
    // 落库不在这里做：交给 CaptureArbiter → 悬浮确认/待确认列表
}
```

> 注意：`onSaveRequest` 只有在**本次 onFillRequest 返回过含 SaveInfo 的 FillResponse** 时才会被调用。所以第 5.2 步里"未解锁也返回 SaveInfo"是必需设计。

### 5.5 Dataset 呈现

```kotlin
fun buildDataset(s: FormSnapshot, e: PlainEntry, order: Int): Dataset {
    val b = Dataset.Builder()
    s.fields.firstOrNull { it.kind in userKinds }?.let {
        b.setValue(it.autofillId, AutofillValue.forText(e.username), presentation(order, e))
    }
    s.fields.firstOrNull { it.kind == PASSWORD }?.let {
        b.setValue(it.autofillId, AutofillValue.forText(e.password), presentation(order, e))
    }
    // 记录"用户选了哪条"，用于 site_mappings 加权
    b.setAuthentication(pendingIntentForSelection(s, e.id))
    return b.build()
}
```

Presentation 用 `RemoteViews`（兼容 API 26+）：一行两列，左 `ImageView`（站点图标/字母头像），中 `TextView` 主标题（条目标题），小字副标题（用户名）。**绝不能把密码放进 RemoteViews**。

### 6.2 事件处理与扫描算法

```kotlin
override fun onAccessibilityEvent(e: AccessibilityEvent?) {
    e ?: return
    if (!settings.a11yCaptureEnabled) return
    if (e.packageName == packageName) return                 // 忽略自己
    if (e.packageName in INPUT_METHODS) return               // 忽略输入法自身窗口

    when (e.eventType) {
        TYPE_VIEW_TEXT_CHANGED, TYPE_VIEW_FOCUSED, TYPE_WINDOW_STATE_CHANGED -> {
            scheduleScan(delayMs = 250)                       // 去抖，避免每次输入都全树遍历
        }
        TYPE_VIEW_CLICKED -> if (looksLikeSubmit(e)) flushCandidate()
    }
}

private fun scan() {
    val root = rootInActiveWindow ?: return
    val snap = NodeTreeScanner.scan(root)                     // 见下
    if (!snap.hasPwdField) return
    // 只在"能唯一定位表单"时才缓冲
    CaptureBuffer.stage(snap)
}
```

`NodeTreeScanner.scan(root)` 核心：

```
BFS 遍历，深度上限 40，节点上限 2000（超限抛弃，防卡死）
对每个 AccessibilityNodeInfo：
  if (className == "android.widget.EditText"
      || className.endsWith("EditText")
      || node.isEditable) {
        val isPwd = (node.isPassword)
                 || (node.inputType and 0x00000080) != 0     // TYPE_TEXT_VARIATION_PASSWORD
                 || (node.inputType and 0x00000010) != 0     // TYPE_NUMBER_VARIATION_PASSWORD
                 || (node.inputType and 0x000000e0) == 0x000000e0  // WEB_PASSWORD
        val text = node.text?.toString()
        val hint = listOfNotNull(node.hintText?.toString(), node.contentDescription?.toString(),
                                 node.viewIdResourceName).joinToString(" ")
        val kind = FieldClassifier.classify(isPwd, hint, node.inputType, text)
        fields += ScannedField(node, kind, text, hint)
  }
```

`FieldClassifier` 规则表（按优先级短路）：

| 判定 | 条件 | 结果 |
|---|---|---|
| 1 | `isPwd == true` | PASSWORD |
| 2 | hint 命中 `验证码|动态码|otp|totp|one.?time|verif` | OTP（不采集） |
| 3 | hint 命中 `用户名|账号|帐号|手机|邮箱|邮件|user|account|login|email|phone|mobile|mail` | USERNAME |
| 4 | inputType 为 email（0x20）或 phone（0x3） | USERNAME |
| 5 | text 匹配邮箱正则 | USERNAME |
| 6 | text 为 11 位数字（中国大陆手机号） | USERNAME |
| 7 | 其他 | UNKNOWN（不采集） |

**站点识别 `SiteIdentifier`**：
- 原生 App：`node.packageName` → `package_norm`。
- 浏览器（`com.android.chrome`、`com.tencent.mtt`、`com.UCMobile` 等）：尝试从 `rootInActiveWindow` 里 `viewIdResourceName` 含 `url_bar` / `address_bar` / `location_bar` 的节点读文本，正则提取 `https?://([^/]+)` → 归一化 eTLD+1。失败则降级为 `browser://<package>` 并要求用户在确认条上手动输入站点名。

### 6.3 悬浮确认条

用 `WindowManager` + `TYPE_ACCESSIBILITY_OVERLAY`（无需 `SYSTEM_ALERT_WINDOW`）添加一条高 56dp 的横条：

```
[🔒 已捕获 ●●●●●●@taobao.com]         [保存]  [改密码]  [忽略]
```

- 显示 10s 自动消失，期间若切换到 App 自身页面则一并移除。
- 点击「保存」→ 启动透明 `CaptureConfirmActivity`（`FLAG_ACTIVITY_NEW_TASK`），走正常保存流程。
- 悬浮条内容**不显示密码明文**，只显示遮蔽后的用户名与站点。

### 6.4 保活与降级

- 前台服务不常驻；依赖系统绑定。
- `ServiceStateMonitor` 每次 `Application.onCreate` 检查 `AccessibilityManager.getEnabledAccessibilityServiceList()` 是否含自己，被关掉则在设置页红点提示。
- 国产 ROM（MIUI/HyperOS、ColorOS）需在引导页明确提示「允许自启动 + 后台弹出界面 + 不省电优化」，并提供一键跳转 `Settings.ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`。

## 7. 通道三：内置 WebView 注入（可选增强）

仅用于 App 内自建 WebView（如内置帮助页、内测站点）：

```kotlin
webView.evaluateJavascript("""
(function(){
  const pwd = document.querySelector('input[type=password]');
  const user = document.querySelector('input[type=text],input[type=email],input[type=tel]');
  if (!pwd || !pwd.value) return;
  AndroidBridge.capture(location.host, user ? user.value : '', pwd.value);
})()
""", null)
```

`@JavascriptInterface` 暴露 `AndroidBridge.capture(host, user, pwd)`，直接投递到 `CaptureBuffer`，`source = WEBVIEW`，置信度 0.95。**必须校验 `webView.url` 的 host 与参数一致**，防止 XSS 伪造。

## 8. 关键时序

### 8.1 首次登录并捕获

```
用户打开 Chrome → 输入 example.com 账号密码
  │
  ├─[Autofill] 聚焦时 onFillRequest → 无匹配 → 仅返回 SaveInfo
  │
  ├─[A11y] TYPE_VIEW_TEXT_CHANGED ×N → 去抖 250ms → scan()
  │        → 命中 pwd + user 框 → CaptureBuffer.stage()
  │
  ├─[A11y] 用户点「登录」→ TYPE_VIEW_CLICKED（按钮文案含 登录/Login）→ flushCandidate()
  │
  ├─[CaptureArbiter] 收到 autofill 侧与 a11y 侧候选
  │        → 5 分钟内同 key(host+username) 去重取后到者
  │        → 查库：无条目 → 状态 NEW；有条目且密码不同 → UPDATED
  │
  ├─→ 悬浮确认条（NEW：「保存」/UPDATED：「更新密码」）
  │
  └─ 用户点保存 → VaultRepository.save() → 字段级加密 → Room/SQLCipher → 列表刷新
```

### 8.2 解锁

```
启动 → SplashScreen
  │  读 vault_meta 判断是否已初始化
  ├─ 未初始化 → Onboarding（设主密码 → 生成 DEK → 写 meta）
  └─ 已初始化 → UnlockScreen
        │
        ├─ 用户输主密码 → KDF(300~500ms, 显示进度) → KEK → 解封 DEK
        │       └─ 用 DEK 解 master_verifier 校验 → 失败计数 +1 + 退避
        │
        └─ 或 生物识别 → BiometricPrompt(CryptoObject) → Keystore 解封 DEK
              └─ Keystore 密钥失效（换指纹/重装）→ 回落主密码
        ▼
      VaultSession.unlock(dek) → 启动自动锁定计时 → 预加载条目索引 → 进列表页
```

### 8.3 自动填充

```
用户点登录页输入框
  → AutofillManager 调 onFillRequest
     → AssistStructureParser: webDomain = "example.com"
     → AutofillMatchRepository: 先查 site_mappings(权重高者优先)
        再查 entries.host_norm = 'example.com'
        再按 eTLD+1 后缀匹配
     → 返回 ≤5 个 Dataset + 「搜索账号本」
  → 用户点选 → AutofillManager 用 Dataset 值填入输入框
     → 我们收到 onFillRequest 里挂的 authentication PendingIntent
        → 累加 site_mappings.weight，更新 last_used_at（异步，不阻塞）
```

## 9. 性能、耗电与稳定性

| 关注点 | 措施 |
|---|---|
| 全树遍历开销 | 去抖 250ms；节点上限 2000、深度 40；单次遍历耗时打点，>30ms 记入本地诊断 |
| onFillRequest 超时 | 系统有 5s 上限；匹配查询走内存索引（解锁时预热 `host_norm → entryId` 映射），目标 < 30ms |
| KDF 阻塞主线程 | 全部在 `Dispatchers.Default`；UI 显示"正在解锁"骨架 |
| 内存 | 解密缓存 LRU 30；大列表用 `LazyColumn` 分页 50 |
| 崩溃安全 | 全局 `CoroutineExceptionHandler` + `Thread.setDefaultUncaughtExceptionHandler`，写本地日志文件（脱敏），下次启动提示导出 |
| 服务被杀 | 每次进 App 校验 Autofill/A11y 服务启用状态；设置页常驻状态卡片 |
| 数据库迁移 | Room `Migration` + `schema_version`；重大变更前强制引导导出备份 |
