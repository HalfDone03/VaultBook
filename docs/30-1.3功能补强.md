# 1.3 功能补强：排序、备注搜索、服务自检、全部恢复、批量去重

## 1. 这一轮从哪来

用户原话：「软件还有什么问题或者功能需要添加优化的」，随后一句「不需要导出备份之类的，其他问题你适当做一下」。

盘点出来八条候选，排掉 CSV 导出与备份相关增强之后，挑了五条动手：设置页看不出系统服务开没开、搜索搜不到备注、列表排序写死在数据库查询里、回收站只能一条一条恢复、批量粘贴会把同一条存成好几份。

## 2. 五项改动

### 2.1 设置页多一段「系统服务」自检

原来设置页只有导出、导入、分类、体检、审计五条，自动填充和无障碍这两个「不打开就等于白装」的开关，在应用里完全看不见。用户在系统设置里关掉、被 ROM 后台清掉、换机重装之后，应用这一侧没有任何提示，只能靠「怎么不自动填了」自己发现。

现在设置页最上面多一段「系统服务」，两条记录，行尾各有「已开启 / 未开启」小药丸，点进去直接跳对应的系统开关页：

- 自动填充读 `Settings.Secure` 的 `autofill_service`，跳 `ACTION_REQUEST_SET_AUTOFILL_SERVICE`，附带本应用包名，进不去时退回系统设置首页；
- 无障碍读 `ENABLED_ACCESSIBILITY_SERVICES`，跳 `ACTION_ACCESSIBILITY_SETTINGS`。

两个状态在页面 `ON_RESUME` 时重读一次，所以从系统设置改完回来，药丸立刻跟着变，不需要退出应用。

读到的字符串是 `包名/类名` 用冒号连起来的一长串，各家 ROM 的写法不一样：有的写全限定类名，有的写 `包名/.包内相对路径`，有的中间夹空段。解析放在 `core/util/EnabledServices.kt` 里做成纯函数，按斜杠切、类名以点开头就补包名、比较不区分大小写，畸形值（缺斜杠、只有斜杠、空段）一律判 false。

### 2.2 搜索现在也搜备注

`EntrySummary.searchText()` 只拼标题、账号、网址、域名，备注从来没进过搜索。可用户写备注就是为了记「这个号是给谁用的」「绑的是哪张卡」——恰恰是最需要搜的内容。

摘要投影里故意没有 `notes_ct`（见 `EntryEntities.kt` 的注释），备注是密文，进摘要就意味着每次列表刷新都要多解一遍所有备注。所以另开一条窄查询：

```
SELECT id, notes_ct FROM entries WHERE deleted_at IS NULL
```

只取两列、只取未删除的，解开之后拼进搜索索引，索引本身仍然在 `items` 变化时算一次。

索引拼接用 `\u0001` 当分隔符而不是空格：空格会被 `Normalize` 折叠掉，字段边界就没了，搜「abc def」这种跨字段的词会误命中。

### 2.3 列表排序可以自己选

原来排序写死在 `EntryDao` 的两条查询里，`favorite DESC, COALESCE(last_used_at,0) DESC, updated_at DESC`——收藏优先、最近用过优先。对「今天要登某个站、但忘了上次什么时候用过」的场景没问题，可要找一条「我记得名字、但很久没动」的记录，就只能靠搜。

现在筛选条右侧加了一个排序胶囊，四种：最近使用（默认，保持原行为）、按名称、最近新建、按分类。

按名称走拼音首字母而不是汉字码点。第一版图省事直接拿 `Pinyin.searchKey()` 当排序键，那个函数返回的是「归一化原文 + 空格 + 首字母串」——排序时先比原文，等于按 Unicode 码点排（「京」U+4EAC 会排在「记」U+8BB0 前面），跟用户脑子里的字母顺序完全对不上。改成只取首字母串（`Pinyin.initials`），首字母相同再往后比，所以「京东 / 结构 / 交易」按 `jd < jg < jy` 排开。

按分类是个稳定排序，先按分类在分类表里的位次，同分类内按名称。未分类和位次表里查不到的分类落到末尾，不参与比较。

选择存在独立的 `list_prefs` 里，没塞进 `simple_vault`——那里放的是库口令，不该混进界面偏好。

### 2.4 回收站能一次全恢复

原来顶栏只有一个「清空」，想恢复只能一条条点。删了十来条想全要回来，得点十来次。

现在「清空」左边多了「全部恢复」，带确认框（文案写清楚「收藏、分类、密码历史都跟着回来」，因为它确实会一起恢复）。走的是 `restoreAllTrashed()`，逐条 `restore(id, now)`，恢复完写一条审计。

### 2.5 批量粘贴不再存重复的

从一段文本里认出十条记录批量保存时，如果库里已经有同名同账号的，原来会照存不误，列表里就出现两条一模一样的。现在保存前先把库里现有的「标题 + 账号」做成集合，撞上就跳过，存完用一句提示报「存了 N 条，跳过 M 条重复的」；全都撞上时说的是「这 N 条库里都已经有了」。

比对用的是 `EntrySignature.of(title, username)`：两边都走 `Normalize.forSearch`（去首尾空白、全角转半角、折叠连续空格、转小写），所以「支付宝」和「  支付宝 」算一条；分隔符用 `\u0001`，因为标题里真的会写竖线，「a|b + c」和「a + b|c」不能撞车。

只看标题和账号、**不看密码**：同一个平台改完密码再存一条，那是用户真想留两条。账号没填和填空格视为等价，填了和没填视为两条。

## 3. 没做的

- **CSV 导出**：用户明确排除。
- **搜索覆盖自定义字段**：自定义字段是变长表，要再开一条查询并做字段级解密，收益比备注小，这轮先不动。
- **列表页加「最近添加」快捷筛选**：排序里已经有「最近新建」，再加一个筛选是重复入口。
- **深色主题手动切换**：跟这轮的五项无关，改动面大，本机无法目视验收。

## 4. 验收要点

1. 设置页最上面多了「系统服务」两条，装完第一次进去都显示「未开启」，点进去能跳到对应系统页，开完返回，药丸变成「已开启」；
2. 随便给一条记录写个只有备注里有的词（比如「房贷」），回列表搜「房贷」能搜到它；
3. 筛选条右侧有排序胶囊，切到「按名称」，列表按拼音字母序排；退出应用再进来，仍然是「按名称」；
4. 回收站里删几条，点「全部恢复」，确认后全回到列表，收藏和分类都还在；
5. 粘贴一段库里已经有的记录批量保存，提示里会报跳过几条，列表里不出现重复。

**仍然没在真机上看过。** 本机没有模拟器、`adb devices` 为空。这轮五项里有三项（服务自检、排序胶囊、全部恢复）是纯界面与系统状态读取，编译通过只能保证不崩，实际布局、药丸配色、跳转后能否正确回读状态，都要装上手机确认；尤其各家 ROM 对 `ENABLED_ACCESSIBILITY_SERVICES` 的写法差异，虽然解析写了容错，但没见过真机数据。
