## 2. 致命：`Utf8.encode` 少了 3 字节分支

这是整个项目到目前为止**危害最大**的一个 bug，而且它伪装得极好：

| 现象 | 说明 |
|---|---|
| 密文正常生成 | AES-GCM 不关心明文是什么字节 |
| 解密正常返回 | 返回的字节和写进去的字节一模一样 |
| AAD 校验正常 | 完整性没被破坏 |
| **内容是错的** | 中文全部变成 `���`，而且**存进去就再也拿不回来** |

单测抓到的样子：

```
expected:<账号本·我的密码管理器> but was:<���·�������>
```

注意中间那个 `·`（U+00B7）是**对的** —— 它是 2 字节字符。
坏的只有中文（3 字节）。emoji（4 字节）也是对的。

原因：`when` 里只写了四个分支

```kotlin
c < 0x80 -> ...          // 1 字节
c < 0x800 -> ...         // 2 字节
isHighSurrogate(c) ...   // 4 字节（代理对）
else -> U+FFFD           // ← 3 字节字符全掉进这里
```

漏了 `U+0800..U+FFFF`。修法见 `app/src/main/java/com/yg/vaultbook/core/crypto/Utf8.kt`：

```kotlin
c < 0x10000 && !isHighSurrogate(c) && !isLowSurrogate(c) -> {
    out[p++] = (0xE0 or (c shr 12)).toByte()
    out[p++] = (0x80 or ((c shr 6) and 0x3F)).toByte()
    out[p++] = (0x80 or (c and 0x3F)).toByte()
}
```

### 这条留下的规矩

**手写的编解码逻辑，必须对 1 / 2 / 3 / 4 字节各有一条测试。**
只测 ASCII 和 emoji 会一起通过，而中间那一档（也就是全部中文）静默全坏。

如果这个 bug 漏到线上：用户存了几十条中文备注，某天想导出来，会发现全是问号。
而密文本身是完好无损的 —— 意味着没有任何办法恢复，只能接受损失。

## 3. lint 报出的 7 类问题，逐条

### 3.1 `MissingPermission`（Error）→ 通知可能让无障碍服务被判异常

`capture/CaptureNotifier.kt` 里 `NotificationManagerCompat.notify(...)` 外面包了 `runCatching`，
但 lint 不认这种「隐式」处理。

真正的风险不在崩溃本身，而在**抛出位置**：这段代码是在无障碍服务里被调用的。
API 33+ 没有 `POST_NOTIFICATIONS` 时 `notify()` 抛 `SecurityException`，
一旦从无障碍服务里抛出去，系统会把这个服务判为异常 —— 用户会看到「账号本已停止」，
捕获功能整体失效，而且**下次得手动去设置里重新打开无障碍**。

修法：先显式检查权限再调用。

```kotlin
private fun hasPostNotificationPermission(context: Context): Boolean {
    if (Build.VERSION.SDK_INT < Build.VERSION_CODES.TIRAMISU) return true
    return ContextCompat.checkSelfPermission(context, Manifest.permission.POST_NOTIFICATIONS) ==
        PackageManager.PERMISSION_GRANTED
}
```

`notify` 之前 `if (!hasPostNotificationPermission(context)) return`，再配 `@SuppressLint("MissingPermission")`。

### 3.2 `MissingApplicationIcon` → 应用没有图标

之前一直是空的（用系统默认图标），原因是最早期刻意不加图标以免 AAPT 找不到资源。
现在补上，而且是**矢量自适应图标**，不需要任何 PNG：

| 文件 | 作用 |
|---|---|
| `res/drawable/ic_launcher_foreground.xml` | 前景：白色锁梁 + 白锁体 + 品牌绿钥匙孔（形成镂空观感） |
| `res/drawable/ic_launcher_monochrome.xml` | Android 13+ 主题图标用的**纯描边版** |
| `res/values/colors.xml` | `ic_launcher_background = #2E6B52` |
| `res/mipmap-anydpi-v26/ic_launcher.xml` | 自适应图标（含 `<monochrome>`） |
| `res/mipmap-anydpi-v26/ic_launcher_round.xml` | 圆形版本（同样含 `<monochrome>`） |

两个细节值得记：

1. **`monochrome` 不能复用 `foreground`**。系统取的是 alpha 遮罩再重上色；
   `foreground` 里锁体是实心填充，直接复用会得到一个实心方块。所以单独做了描边版。
2. **目录名不能去掉 `-v26`**。我先按 lint 的意思改成 `res/mipmap-anydpi`，
   结果 `processDebugResources` 直接失败：

   ```
   AAPT: error: resource mipmap/ic_launcher not found
   AAPT: error: resource mipmap/ic_launcher_round not found
   ```

   aapt2 会忽略不带版本限定符的这个目录。所以目录改回 `mipmap-anydpi-v26`，
   并用 `app/lint.xml` 定向忽略那一条 `ObsoleteSdkInt`（文件里有完整注释说明为什么）。

### 3.3 `MonochromeLauncherIcon` ×2

`android:icon` 和 `android:roundIcon` 两个入口都要声明 `<monochrome>`，只改一个会漏另一个。

### 3.4 `RedundantLabel`

`MainActivity` 上的 `android:label` 与 `application` 的重复，删掉 activity 那个。

### 3.5 `ComposableNaming`

`private fun header(...)` 是 `@Composable` 但首字母小写。
Compose 的约定是「返回 Unit 的 `@Composable` 用大驼峰」，因为它在调用处看起来像标签。
改成 `Header(...)`，同步改唯一调用点。

### 3.6 `ObsoleteSdkInt`

`DeviceKeyStore.kt` 里 `if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.N) { setInvalidatedByBiometricEnrollment(false) }` ——
`minSdk` 已经是 26，这个判断永远为真。直接调用，去掉包裹。

### 3.7 `AutoboxingStateCreation` ×3

`CategoryManageScreen` / `TrashScreen` / `VaultApp` 里 `mutableStateOf(0)`。
`Int` 走 `mutableStateOf` 会被装箱成 `Integer`，每次读写都可能分配对象。
改 `mutableIntStateOf(0)`，它内部用 `MutableIntState` 存原始类型。

### 3.8 `ConstantLocale` ×2

`EntryDetailScreen` 与 `TrashScreen` 把 `SimpleDateFormat(..., Locale.getDefault())`
存成了**静态字段**。静态字段在类初始化那一刻就把 locale 定格了 ——
用户中途把系统语言从中文切到英文，这些时间仍然按中文排版。
改成每次调用新建（`SimpleDateFormat` 本来就不是线程安全的，也不该共享）。

## 4. 顺手补的两处（lint 不会报，但会慢）

Room 的 `@ForeignKey` 会让 SQLite 在删除被引用行时反查子行。没有索引就是全表扫。
lint 的 `Room` 检查已经提示了这两条，补上：

| 表 | 新增索引 | 为什么 |
|---|---|---|
| `entries` | `idx_entries_category`（`category_id`） | 删分类时要 `UPDATE entries SET category_id = NULL WHERE category_id = ?` |
| `site_mappings` | `idx_map_entry`（`entry_id`） | 删条目时 CASCADE 要按 `entry_id` 找映射行 |

注意 `idx_map_host` 的首列是 `host_norm`，**不能**替代 `entry_id` 上的单列索引。

另外 `capture/CaptureNotifier.kt` 头部有一段注释已经过时（写着"本工程刻意没有自定义 launcher 图标"，现在有了），
顺手改成解释「为什么通知小图标仍用系统资源」（彩色自适应图标当通知图标会被渲染成一团白块）。

3. **主题图标（monochrome）没在 Android 13+ 设备上看过效果**。矢量形状是照着安全区画的，

   这是「工具认为冗余、实测必须保留」，理由写在文件注释里。如果以后 minSdk 提到 26 以上
   的某个版本导致这条结论变化，要回来看一眼。

## 7. 这一轮的方法论

值得留下来的三条：

1. **先让编译器说话，再让 lint 说话，最后才靠人眼。**
   在没有任何工具链的时候，这 8067 行代码"看起来都对"；
   真编译一次冒出 30 多条错误，lint 又冒出一批。人眼复核的命中率远低于工具。
2. **错误分两类：工具能查的，和工具查不出来的。**
   这一轮把前者清干净了（lint 0/0）。剩下第 6 节那五条都属于后者，
   其中 1、2 两条**必须由用户在真机上完成**，不是我能代劳的。
3. **加密相关的代码，测试要盯「内容」而不是「流程」。**
   `Utf8` 那个 bug 里，加密/解密/AAD 校验每一步的返回值都对，
   只有最后拿出来给人看的字符串是错的。如果只测"加密能解回来"就永远发现不了。
