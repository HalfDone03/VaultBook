# 1.11：语料表扩到十九组、二百八十六条

## 起因

上一版把「粘贴一段文字自动认出账号密码」从几条正则改成了一张样本表驱动的规则集：先列出人真会粘到的东西，再让解析器一条条去对，对不上的补规则。这一版继续往样本表里加料——用户的原话是「你再多拿点样本多跑点，把识别的规则完善吧」。

## 做法

样本表 `CredentialParserCorpusTest` 里每条是「名字、粘贴内容、期望的若干条记录」，比对标题、账号、密码、备注四项，不比网址（网址归一化后写法太多，比它只会制造噪声）。一次跑完全部条目，把所有不符的一次性列出来，再逐条定位。

这次从十三组九十七条扩到十九组二百八十六条，新增的六组分别覆盖：

- 第十四组「换个说法抄同一件事」：手机号配登录密码、英文表头、密码里带空格逗号井号、只有数字的密码、同一行两遍键值、横线分两组、方头卡片同一行、密码结尾句号、平台上带引号等。
- 第十五组「群里转发的与别处的怪写法」：聊天记录夹着账号密码、繁体字段名、网址带端口、IP 当网址、顿号当分隔、制表符四列、确认密码重复出现、纯数字六位密码、站点名与账号粘连、全角竖线分隔、密码里有井号与美元、前后各有一句废话等。
- 第十六组「开发者后台与笔记软件里捞出来的」：AppID 配 AppSecret、JSON 只有账号密码、XML 里套 CDATA、Markdown 反引号与加粗、Markdown 表格的分隔行、HTML 的 `<tr><td>` 表格、四键一行带网址、书名号包平台名、账号带身份说明、密码含等号加号等。
- 第十七组：微信里两行抄一条、同一平台两条连写、ini 段落、五列表格多一列无关、登录 ID 带空格、密码是中文、序号加顿号、英文缩写平台名、冒号链带中文账号、方头括号里带编号等。
- 第十八组「连接串、命令行、引号」：`postgres://user:pass@host`、`redis://:pass@host`（没有账号）、`mysql -u x -p y`、竖线两边都带键名、聊天记录带发信人、引号包住整段键值、两列制表符带引号等。
- 第十九组：前面顶着时间戳、全角空格当分隔、密码是一串符号、密码是 base64、会员号当账号、英文表头写全称、斜杠隔开两个键、中文括号包着整条、yaml 值带引号、json 最外层是数组、先密码后账号、书名号包平台名、备注是一句带逗号的话等。

## 这一轮真正修掉的病

样本一多，暴露出来的多数不是「少写了一条正则」，而是几个根子上判断错了：

- 链接里的密码带 `#` 时整条链接认不出来。原来取 authority 时先按 `#`、`?` 截断再找 `@`，`ftp://demo:Ftp#2024@host/` 的 `@` 会被一起剪掉，链接退化成按位置猜，密码被啃成 `Ftp#2024@host`。改成只截到路径为止，`@` 取最后一个。
- 值尾巴上挂着半个字段名。`确认密码`、`重复密码` 进了字段名表，但正则从值的位置往后找下一处字段名时，前面那个空格落在搜索起点之外、边界判不成立，于是值一路吃到行尾（`Rp@111111 确认`）。与其在正则上绕，不如事后把「空格 + 残缺字段名」这截剪掉。
- 中文输入法下的空格是 U+3000，`\s` 不认它。`账号　zh_1　密码　…` 这种整行没人要，或者第一个字段一路吃到行尾。字段名边界与分隔符都补上了全角空格。
- 每个「第零步命中就返回」的快捷识别都不会走到标题兜底，`淘宝🛒` 这样的卡片头就丢了标题。改成统一过一个 `named()`：命中后若还没标题，回到原文里再找一次。
- 表情过滤不掉。Kotlin 的 `Char` 是 UTF-16 单元，🛒 是两个代理项，各自都小于表情码点区间，只按码点过滤等于没过滤。
- 右括号被啃掉。值末尾的闭合符原来无条件剥，`adm_1（管理员）`、`（内部使用）` 会把括号吃掉一半；改成只在「多出来的闭合符」上剥。
- 引号剥错层。整段首尾都是引号时不能闭眼剥一层：`"淘宝","tb_72","Tb@727272"` 是三格 CSV，剥掉外层就把配对打乱了。
- 备注里的冒号等号被当字段名。备注改成「取到行尾」，只在「空格后冒出字段名」处截断。

## 刻意不认的

- 中文句子里的两句感叹（`账号是a 密码是b，记得改`）——尾句当备注，剩下的照认，但不为它专门写规则。
- 一行里两组以上凭据（`账号a 密码b 账号c 密码d`）——按第一条算，第三条起不猜。
- 纯汉字两段当账号密码（`淘宝 购物`）——真账号密码极少是纯汉字，猜它只会把说明文字存成凭据。
- 括号里只有「必填/选填/说明」这类占位词——不认，避免表单说明被存成凭据。
- 深层嵌套 XML（带命名空间、带属性又带子元素）——只认浅层配对与属性两种。

## 验证

- 单元测试 31 个测试类、502 个用例，0 失败。
- 样本表 19 组 286 条全部通过。
- 包内核对：`versionCode 210`、`versionName 1.11`、`minSdk 26`、`targetSdk 35`、`arm64-v8a`，解包 dex 里能查到 1.11 字样。

## 还没做

- 真机验收仍是空白：粘贴框下方逐条列表的限高、整行点击热区、等宽字体下的中文回退、按行号记的对调状态在重排后是否错位，这些只有装到手机上才看得见。
- 嵌套很深的 XML 与带验证码的混排记录，仍按上面的「刻意不认」处理。
- 一行多组凭据仍只取第一组。
