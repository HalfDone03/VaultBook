## 二、版本归 1.0

- `versionName = "1.0"`，对外就叫 1.0。
- `versionCode = 100`，**不是 1**。

原因：上一个装出去的包是 `versionCode 17`。Android 只允许 versionCode 递增，装 `versionCode 1` 会被判成降级而拒绝（`INSTALL_FAILED_VERSION_DOWNGRADE`）。要么用户先卸载（数据一起没了），要么把内部号抬高。选后者：1.0 用 100，以后 1.0.1 → 101、1.1 → 110，一眼能看出对外版本。

第一次构建曾误设成 `versionCode = 1`，出包后核对 `aapt2 dump badging` 才发现，随即改回 100 并重新出包、重新上传。

## 四、README 重写

## 五、踩坑

| 现象 | 原因 | 处理 |
|---|---|---|
| README 写入报 `file has not been read` | 写入工具要求先读后写，防止覆盖未读内容 | 先 `read` 再 `write` |
| `git push` 卡 21 秒超时 | DNS 把 `github.com` 解析到 `20.205.243.166`（该 IP 当前不可达）；`api.github.com` 与 `140.82.x` 段正常 | 本机起了个只转发到 `140.82.121.4:443` 的 CONNECT 中继，`git config http.proxy` 指过去。属本机网络环境问题，与工程无关 |
| 中继脚本编译报「当前上下文中不存在名称 buf」 | `Add-Type` 读 UTF-8 无 BOM 的 C# 源码时按 ANSI 解码，中文注释把下一行吞了 | C# 部分改为纯 ASCII，中文只留在 PowerShell 注释里 |
| `git push` 返回 exit code 1 但实际成功 | PowerShell 把 stderr 当错误流 | 看 `* [new branch] main -> main` 与远端文件数确认 |
