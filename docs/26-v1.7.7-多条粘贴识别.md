# v1.7.7 多条粘贴识别与「只存标题+密码」

> 起因：用户反馈「粘贴界面可以识别多个账号密码保存，然后可以只保存密码+标题之类的」。
> 一次粘贴里常常是好几条记录（聊天记录抄下来的、记事本攒的），原来只认第一条，剩下的要靠手抄。

---

## 1. 原来的行为

`CredentialParser.parse(raw)` 是**单条**解析：一次 `KV_REGEX` 扫描 + 兜底按位置猜，返回一个 `Result(username, password, url, title)`。

多条文本喂进来时，键值正则会一路覆盖，最终只剩最后一组（或者把整段当成一个超长值）。所以粘贴十条，只能存一条。

## 2. 现在怎么切

新增 `CredentialParser.parseMany(raw): List<Result>`，**四种形状依次试，命中即用**：

| 顺序 | 判据 | 适用 |
|---|---|---|
| ① 一行一条 | 每一行用 `splitInline` 都能切出 ≥2 段 | 从表格/聊天里复制的规整列表 |
| ② 空行分段 | 按 `\n\s*\n+` 切，每段各自 `parse` | 手写记事本，条与条之间隔了空行 |
| ③ 重复键切块 | 见下 | 全挤在一行或没有空行 |
| ④ 退回单条 | 以上都不成立 | 普通的一次粘贴 |

判据统一是「切出 ≥2 条，且**每条都 `hasCredential`**」。只要有一条认不出账号也认不出密码，就整体退回单条——宁可少切，不能把一段话切成两条垃圾。

### ③ 重复键切块的做法

`recordStarts(text)` 扫一遍所有键值匹配：

- 遇到 `密码` 键 → 记 `seenPassword = true`；
- **在已经见过密码之后**，又遇到 `标题` 或 `账号` 键 → 这里就是下一条的起点，切一刀，`seenPassword` 归零。

切点优先取该键所在行的行首；如果行首不在上一个切点之后（说明两条挤在同一行），退化成键本身的起始位置。

### 为什么把「平台」加进标题别名

`title` 组原本是 `title|name|app|标题|名称|站点|应用|app名`。用户抄写习惯是：

```
平台：淘宝  账号：xxx  密码：yyy
平台：京东  账号：zzz  密码：www
```

「平台」不在别名里，正则认不出这是标题键，第一块的 title 就是 null，第二条又会从「账号」开始切——两条都缺标题。补上 `平台|软件` 之后两个问题一起解决。这条是测试先红后绿的直接原因。

## 3. 批量保存对话框

识别出多条时**不直接写库**，弹 `BatchSaveDialog`：

- 每行一个 `Checkbox`（默认全勾）+ 标题 + 「账号」或「只有密码」+「已认出密码」；
- 底部一个 `Switch`：**「只存标题和密码」**，副标题「不要账号，适合只记得住平台名的时候」。打开后 `username` 一律传 `null`；
- 确认按钮写「存 N 条」，保存中禁用。

逐条走已有的 `repo.createEntry(draft)`，每条之间互不影响；中途抛异常只报「连第 N 条就停了，前面 N 条已经存好」，不假装成功。

标题的回退顺序是 `title ?: url ?: username ?: ""`，最后由仓储层把空标题兜底成「未命名」。

## 4. 入口不止一个

| 位置 | 行为 |
|---|---|
| 编辑页「智能粘贴」/ 手动粘贴框 | `parseAndApply` 改走 `parseMany`；多条直接开批量框 |
| 新建页自动偷看剪贴板 | 多条时**不自动填**，在表单上方显示一张卡「剪贴板里有 N 组账号密码」，按钮「看看」/「忽略」 |
| 从别的应用分享文本进来 | 同上，走 `parseAndApply` |
| 单条粘贴 | 完全保留旧路径：识别 → 提示卡 → 「填入」 |

单条不走批量框，是因为用户此刻要的是「快速填一条」，弹个列表反而多一步。

## 6. 没做的

| 没做 | 原因 |
|---|---|
| 识别「网址/邮箱/手机号」多组但**没有密码**的表格 | 那种更像通讯录，误存一堆只有账号的条目更麻烦 |
| 批量保存时逐条选分类 | 一次粘贴通常属于同一批，先存后归类更顺手 |
| 批量里自动去重（和库里已有条目比） | `createEntry` 不去重，同名会变两条；改去重要先设计「合并还是跳过」，留到后面 |
| 识别过程中的进度动画 | 几百行也就几十毫秒，加动画反而是噪声 |
